## Результат для продукта

Открыть готовый запуск → увидеть важные спорные места → проверить состав требований → сохранить решение → повторно открыть тот же результат → получить пакет для менеджера с теми же статусами. Без повторного модельного запроса при просмотре/проверке/экспорте. Этот путь даёт практическую ценность, которую можно проверить на защите.

Ориентир 4–6 часов после первой поставки viewer; обязательный срез ограничить 3–4 часами, расширение перенести на утро при задержке backend. Первый самостоятельный PR — через 60–90 минут, не ждать завершения всех экранов.

## Владение и зависимости

Ты не один: Егор владеет E5/E8 контрактами и логикой очереди; Codex — application/run_store/model/privacy/pipeline/Docker/locks. Твои: `prototype/web_app.py`, `prototype/web_report.py`, `prototype/static/`, `prototype/tests/test_web_*`, UI-fixtures и `docs/reviews/vanya-night-*`. Не рассчитывай score и право передачи в JS. Не добавляй второе хранилище запусков или прямой OpenAI-вызов.

Сначала зафиксируй тонкий service adapter в своём транспорте с fake service для тестов. Его контракт — docs/21 и ночной план docs/25. Backend Codex отдельно реализует create/get/report/confirm/cancel/delete; пока операции нет, UI показывает её недоступность, а не имитирует успешную запись. Локальный просмотр импортированного JSON работает независимо.

## V11.1 · P0 — экран направленной проверки

1. Сверху остаются режим, обработано N/M, версия политики и неподтверждённость. Нельзя заменить их зелёным «готово».
2. Очередь E8: причина, вакансия/требование, приоритет и конкретное действие; переход сразу к двум фрагментам документов. До E8 используй явные текущие evidence/mandatory signals и помечай это как временную проекцию; не придумывай semantic confidence.
3. Состав требований: список + обязательность + uncovered. Пользователь подтверждает именно показанную ревизию отдельной кнопкой. Не ставить checkbox автоматически при загрузке.
4. Статус модели, структурная проверка, подтверждение списка и решение рекрутера отображаются отдельно. Нажатие «прочитано» не превращает unknown в full.
5. При stale/version conflict перечитай актуальные данные, покажи причину и предложи повторную проверку. Не делать скрытую повторную мутацию на новой версии.
6. Конфликт условий и предупреждение privacy о возможной потере навыков не пропадают после открытия/печати. Профиль E5 и сравнение E7 подключаются через уже выданные поля, без самодельных выводов.

**Приёмка:** keyboard-only прохождение, длинные русские цитаты, идентичные цитаты под разными заголовками, unknown/partial/fail/full, stale response, 2 клика подряд. Вызовы read/review/export не инициируют analyze; fake counter это подтверждает.

## V11.2 · P0 — открыть, повторить просмотр, экспортировать

- После перезагрузки страницы опубликованный запуск открывается по opaque run_id через backend. Список содержит безопасную метку/дату/режим/статус; исходные пути не отправляются клиенту.
- Импортированный произвольный report.json обозначен как внешний непроверенный файл. Его claimed confirmed/reviewed state не считается доверенной серверной историей, он не может подтвердить другой запуск.
- Кнопка запуска не создаёт дубликат при двойном клике/переподключении. Idempotency backend сохраняется; новый явно запрошенный анализ — отдельный запуск и отдельная стоимость.
- При обработке отображаются реальные стадии/отмена; состояние interrupted после рестарта не является success. Предыдущий опубликованный результат доступен, незавершённый временный каталог не показывается как готовый.
- Пакет менеджеру использует ту же выбранную вакансию и ревизию, что экран. Режим replay/mock/live, предварительность и неполнота сохраняются в печати. Нет скрытого нового вызова модели для «красивого текста».

**Приёмка:** открыть A, открыть B, вернуться к A; обновить страницу; экспортировать спорный/неполный; неизвестный run_id; намеренно испорченный JSON. Ничего от B не попадает в A, неподтверждённый импорт не получает серверные права.

## V11.3 · P1 — удаление и состояния отказа

После готового `delete_run` Codex добавь явное удаление выбранного запуска с понятным перечнем: обработанные копии/отчёты/решения. Не обещай удаление исходного файла пользователя или данных провайдера. Удаление активного запуска должно возвращать безопасный отказ либо ждать подтверждённой остановки по контракту backend — не выбирать поведение самостоятельно.

После удаления карточка/экспорт недоступны; соседний запуск сохранён. Нельзя принимать абсолютный путь, `..`, чужой id или symlink как объект удаления. Проверки доступа принадлежат серверу; скрытая кнопка не является защитой.

## V11.4 · обязательная приёмка и передача

Не дублируй V7: используй его runner/CI и дополни конкретным браузерным путём. Нужны:

1. 1 синтетический успешный и 1 спорный сценарий с записанными ожидаемыми действиями; дополнительно incomplete/stale/отказ backend.
2. Локальные проверки XSS в имени/цитате/комментарии, traversal, Host/Origin/session token, лимиты загрузок. Не отправлять реальные данные в агента/браузерные внешние сервисы.
3. Короткая запись 90–120 секунд на указанном SHA: загрузка или открытие → рейтинг → цитата → спорное условие → пакет менеджеру. Если запуск только replay/import — это видно в записи.
4. `docs/reviews/vanya-night-handoff.md`: SHA/ОС/браузер/команды, что подключено к реальному service, что проверено только fake service, список блокеров. Скриншот сам по себе не доказывает сквозной путь.

Если Codex/E8 задержались: сдаёшь работающий импорт/просмотр/печать, adapter + тесты, остальные controls отключены с причиной. Не удерживай полезный PR из-за одной зависимости. Нельзя публиковать имитацию подтверждения как настоящее сохранение.
