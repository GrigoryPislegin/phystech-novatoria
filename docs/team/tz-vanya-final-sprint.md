## V3 — рабочий экран рейтинга и доказательств

**Проблема:** сейчас рекрутер должен читать длинный Markdown/JSON; трудно быстро проверить, почему одна вакансия выше другой.

**Реализация:** офлайн viewer загружает report.json пользователем. Сверху — режим (replay/live), обработано N/M, состояние проверки требований и предварительность. Список вакансий: место/название или id, балл L/H с пояснением, обязательные условия и число спорных/неизвестных строк. Таблица выбранной вакансии: требование, обязательность, четыре статуса, факт/цитата, комментарий проверки и вопрос. Клик раскрывает фрагменты CV и вакансии рядом. Фильтры «всё / требует проверки / не указано / несоответствия», поиск по требованию. Смена фильтра не меняет рейтинг и не делает сетевой вызов.

Не делай «подтверждённым» всё, что имеет full/complete. У отсутствующих E3/E4 полей показывай неподтверждённость. Значение 100 не называется вероятностью найма. Равные места не превращай в уникальный порядок. При incomplete сверху заметно N/M и список пропущенных, а первое место подписано предварительным. Пустой/неверный JSON — понятная ошибка, ранее открытый отчёт не смешивается с новым.

**Приёмка:**

- Текущие success/disputed открываются; все четыре статуса видны в двух сценариях.
- Проверяющий за ≤3 действия находит обе цитаты конкретного требования. Это UX-цель, проверяемая записью прохода, не готовая метрика.
- Fixture со второй упавшей вакансией показывает неполный результат и правильные успешные строки.
- Fixture с HTML/script в цитате отображает текст, скрипт не выполняется. Нет внешних запросов/CDN/шрифтов/аналитики.
- Файлы настоящих CV не нужны: test fixtures вымышленные, mode указан. По возможности снимки 1440×900 и 1280×720, таблица не обрезает действия.

## V4 — парсер и понятные отказы

**Проблема:** обязательный текст в структуре DOCX может исчезнуть; пользователь видит общий ValueError.

На основе своего documents.py добавь случаи: непустой колонтитул, вложенная таблица, текст в shape/textbox (сначала воспроизвести), смешанные пустые/текстовые страницы PDF, Unicode/переносы/таблицы. Для неподдерживаемой структуры выбери корректное извлечение в порядке документа либо явный отказ безопасным кодом. Не возвращай частичный текст как полный; не пытайся срочно строить OCR.

Сохраняй `read_document(Path)->str`. Код ошибки — whitelist; raw исключение, путь и содержание документа не идут в журнал. Составь отображение code → понятная причина → действие и передай Codex для CLI. Веб-транспорт использует то же отображение. Лимиты до извлечения: 5 MB/документ, 100 PDF-страниц, 60 000 символов, DOCX expansion 20 MB; новые лимиты/тайм-ауты явно документировать. Отдельно согласуй с Codex проверки количества и symlink до парсинга (N4), не исправляй __main__.py сам.

**Приёмка:** реальные библиотеки читают синтетические файлы; важный фрагмент найден либо конкретно отклонён; пустой/повреждённый/переполненный/неподдерживаемый вход не вызывает модель и не раскрывает пути. Проверить 20/21 файл на application boundary с mock, без API. Resource timeout нужен, если воспроизведён файл, обходящий ограничения по времени; не обещать ограничение только по размеру.

## V6 — набор качества по реальным областям кейса

Python/Java недостаточно. В условии три направления: frontend, учёт и движение основных средств, куратор образовательного процесса. Создай **полностью вымышленные** fixtures: минимум по два CV на область (явное соответствие и неоднозначный/неподходящий), три вакансии. Это 6 CV × 3 вакансии как план покрытия, не требование уже сейчас оплатить 18 сравнений.

Для каждого case: id, происхождение synthetic, тексты, ожидаемые ключевые факты/требования, допустимые статусы/отношения и основание, `draft`/`expert_confirmed`. Отдельные cases: отсутствие навыка в тексте, явное отрицание, синоним, конкретный стаж, пересекающиеся периоды без двойного счёта, образование, уровень задачи, заголовки обязательности, нерелевантный документ, инструкции внутри CV. Егор подтверждает спорные ожидания; ты не объявляешь собственную разметку экспертизой.

В `evaluation/` сделай runner проверок **сохранённых результатов** по fixture/manifest: целостность цитат/id, неизвестное не равно отрицанию, покрытие требований по указанному эталону, допустимые отношения ранга, отсутствие неподтверждённых утверждений. Ошибка/пропуск имеет отдельный статус, а не засчитывается за правильный unknown. Выведи знаменатели, failures и режим данных в JSON+Markdown. Runner не вызывает API автоматически.

Минимальный keyword baseline — отдельный явно названный метод без LLM; только если успеваешь после основного runner. Сравнивать на тех же входах и правилах, не выдавать baseline за реальное обучение. Названия/порядок файлов/ФИО меняются в нейтральных вариантах, ожидаемая профессиональная оценка сохраняется. При изменении информации ожидание может измениться — не делай ложный тест инвариантности.

**Приёмка:** offline команда, документированный формат и новый пример; намеренно ошибочный отчёт роняет проверку; JSON-результат показывает 0/не запущено, если нет live-данных, а не 100% точность. Минимум одна синтетическая вакансия/резюме в DOCX и PDF, не только строки в Python. Новых зависимостей без согласования lock не добавлять.
