## C1 — первая правка, до защищённого live

R1: проверяй декодированные строковые данные до сериализации и после разбора ответа. Сохрани проверку вложенных полей/списков и динамических ключей, неподтверждённых refs и остаточных находок. Не расширяй issued_refs и не выключай scan ради прохождения. Тесты: настоящая ссылка после LF/TAB, кавычки/слеши, вложенный payload и ответ; поддельная ссылка отклоняется до SDK.

R2: обеспечь безопасное журналирование при наследованном OPENAI_LOG=debug. Payload/ответы/ключи/DSN не должны попадать в stdout/stderr. Сохрани безопасный код стадии. Проверка отдельным процессом на настоящем закреплённом SDK с MockTransport и вымышленными контрольными значениями, без сети. Не читать .env ради этой проверки.

Готово, когда регрессии сначала воспроизвели обе проблемы, затем проходят; все тесты CLI и оба replay проходят. Ближайшее окно до 12:40 — только проверенная небольшая поставка; если она не готова, оставь её вне замороженного демо и заверши после консультации, до любого защищённого live. Не смешивай её с изменением формулы.

## C2 — подключить разработку Егора

До заморозки честно раздели «обработаны все вакансии» и «состав требований подтверждён человеком»: complete=true по извлечённому списку не доказывает полноту исходной вакансии. Покажи ограничения в отчёте и демонстрации. Проверки контекста реализует Егор в E3, подтверждение списка/обязательности — в E4. Не дублируй его разработку. По handoff проверь контракт, подключи к run_pipeline/CLI и отчёту; обнови SYSTEM только в своей ветке. Файл подтверждения сохраняй локально с закрытыми правами, привязкой к обработанному источнику и всему списку; финальный отчёт различает состояние обработки и проверки. Не добавляй UI ради этого шага.

Приёмка: пропущенное обязательное Go не становится подтверждённым полным результатом; «Не работал с Python» не принимается как доказанное full по одному слову; нерелевантный факт не подтверждает fail; широкая цитата через «Обязательно/Желательно» не подтверждает обязательность SQL. Структурные тесты и ручная оценка синтетических случаев различаются в отчёте. Regex или вторая модель сами по себе не доказывают семантику. Веса/порог/partial меняй только после зафиксированного ответа эксперта. Не вводи автоматический отказ кандидату.

## C3 — собрать privacy_core и упаковать

Наш компонент `privacy_core` использует технологию Certum: детекторы, псевдонимизация, повторная проверка, отдельный vault. Техническое имя внешнего пакета `certum_core` в импортах и штатных командах сохраняется. Приложение Certum, его UI, чужой развёрнутый сервис и личная база не нужны. Репозиторий/ревизия нужны только для получения нужного модуля и происхождения. Не заменяй технологию самописным regex, облачным relay или молчаливым обходом.

Сверь docs/17-certum-local-setup.md. Подготовь единый Python 3.12 runtime и совместимые версии зависимостей CLI/core: сейчас SDK 2.54.0 и 3.29.0 в разных locks, у core нет python-docx. Не обновляй вслепую. Зафиксируй воспроизводимый способ получить только нужный core и модели, Docker/Compose для нашего приложения с отдельной локальной PostgreSQL, миграциями, tenant/vault и новыми секретами. Секреты создаются локально; исходный Certum и его данные не изменяются. Если разрешённый способ передачи core не установлен — укажи конкретный блокер, без копирования всего продукта.

Приёмка: чистый запуск/остановка по README; V2 повторяет на другом компьютере; при недоступности core/моделей/БД вызов модели не выполняется. Локальный smoke и совместный защищённый E2E имеют отдельные результаты. Ранее разрешённый live до $1 уже состоялся: новый платный прогон обсуждается отдельно, на синтетике, с конкретным лимитом. Само это ТЗ не разрешает повторные API-расходы; реальные CV не отправлять. Sol вне обязательной поставки.
