# Егор: подключение и первая задача

Твоя зона — логика продукта и независимая проверка. Вручную размечать весь набор резюме не нужно. Используй свою подписку Claude Max, включая **Opus**. Работа агента над кодом оплачивается подпиской; $74 OpenAI оставляем для вызовов самого продукта.

## Подключение

1. Прими приглашение GitHub на аккаунте `startupone12` (отправлено ранее; принятие ещё не проверено).
2. Клонируй ветку командного пакета и создай свою ветку от общей согласованной базы:

```sh
git clone --branch codex/cli-recruiter-prototype https://github.com/GrigoryPislegin/hackathon-phystech-nanimai.git
cd hackathon-phystech-nanimai
git switch -c egor/product-review
```

Если README не похож на этот или нет prototype/, сначала получи актуальную ветку от Григория: не начинай работу по старой подготовке.

3. Установи Claude Code по [официальной инструкции](https://code.claude.com/docs/en/setup). Для Mac с уже установленным Homebrew:

```sh
brew install --cask claude-code
claude
```

Войди через свой Claude Max. Не выбирай оплату API. Если CLI уже есть, повторная установка не нужна. ОС пока не подтверждена; на Windows используй вариант официальной инструкции, команды проекта ниже удобнее выполнять в WSL.

4. Подключи общую зафиксированную библиотеку навыков:

```sh
git clone https://github.com/obra/superpowers.git vendor/superpowers
git -C vendor/superpowers checkout 22f0b463e7a5e579904dd6211a520321035526f7
python3 scripts/setup_claude.py
claude --model opus
```

Если vendor/superpowers уже существует, пропусти clone и проверь ревизию; не удаляй каталог вслепую. Установщик меняет только `.claude/` проекта, глобальные настройки не трогает. На Windows без WSL создание symlink может требовать Developer Mode.

5. В новой сессии проверь `/agents`: `hackathon-scout` (Haiku) и `hackathon-opus-reviewer` (Opus); `/skills` — Superpowers. Через `/model` можно выбрать доступную Fable для основной работы, а ревьюер останется Opus. Не закрепляем выдуманную версию: фактическую доступность показывает твой аккаунт. Если Opus недоступен, зафиксируй это, не включай платный API автоматически. [Модели](https://code.claude.com/docs/en/model-config), [роли](https://code.claude.com/docs/en/sub-agents).

## Какие навыки использовать

`brainstorming` — только нерешённый продуктовый вопрос; `writing-plans` — короткий план; `executing-plans` — работа в основной сессии; `systematic-debugging` — реальная ошибка; `requesting-code-review` / `receiving-code-review` — одно ревью и разбор; `verification-before-completion` — доказательства результата. Для изменения кода также `test-driven-development`. Полная библиотека доступна, но не загружай все навыки на каждую задачу. Не включай рой исполнителей.

## Первая задача: готовый текст для Claude

> Прочитай CLAUDE.md, docs/12-expert-answers.md, docs/15-architecture.md, docs/14-team-kickoff.md и prototype/. Моя зона — проверка логики и подготовка консультации. Ты не один в проекте: Григорий владеет скорингом, защитой и интеграцией, Ваня — документами и запуском. Не редактируй их код. Используй одного hackathon-opus-reviewer для проверки четырёх статусов, формулы, обязательных требований, цитат и неполного рейтинга. Никаких реальных CV или ключей в контексте. Подготовь docs/reviews/egor-review.md: максимум пять доказанных проблем с примером, важностью и предложением; отдельно вопросы, где нужно решение заказчика. Подготовь docs/reviews/consultation-brief.md: объяснение продукта за 30 секунд и пять вопросов на десятиминутную встречу. Синтетические примеры пометь. Новые агенты не создают агентов. Основной агент запускает доступные проверки; ревьюер только читает. В конце перечисли файлы и ограничения. Не пушь и не сливай без моей команды.

**Готово**, когда есть два коротких документа, проблемы подкреплены воспроизводимыми примерами, а вопросы не повторяют уже полученные ответы. Нет требования придумать проблемы или вручную оценить все пары.

Первыми вопросами на консультации: явные обязательные требования и допустимые исключения; как учитывать неизвестные сведения; что важнее при спорном порядке вакансий; как оценят качество на скрытом наборе; ограничения внешних моделей и обезличивания. Подробный список — в архитектуре.
