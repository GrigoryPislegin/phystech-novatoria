## N-C1a · P0 — минимальный реестр запусков для V8

Согласовать с Ваней конкретный service adapter за 30–45 минут разработки. Контракт операций из docs/21: start/get/report/cancel; сеть/HTTP остаётся в web_app. Один активный анализ на процесс, без распределённых очередей/Redis/Celery. Дополнительный параллельный старт получает busy; просмотр завершённых результатов остаётся доступен.

- Сервер выдаёт opaque run_id и хранит относительные пути внутри одного private root. Не открывать произвольный путь клиента. Каталоги 0700, файлы 0600; raw inputs/manifest не в журнале и не в Git.
- Для review хранить локальный снимок **обработанных** источников и версию требований. Оригиналы пользователя не копировать без необходимости и не включать в публичный report/prompt; перечень фактически сохраняемого описать.
- start с тем же idempotency key и тем же вводом возвращает тот же запуск; тот же ключ с иным вводом — конфликт. Повторный клик/переподключение не создаёт второй расход. Область ключа — текущая локальная сессия, не глобальный пользовательский секрет.
- Состояния queued/running/complete/partial/failed/cancelled/interrupted описаны явно; complete относится к обработке. На рестарте running становится interrupted, не возобновляет оплачиваемые вызовы сам.
- Сохранение snapshot/результата атомарное. Незавершённый staging не показывается как report. Успешная часть остаётся при предусмотренной остановке, а ошибка экспорта не создаёт ложный success.
- Cancellation не запускает новые запросы после checkpoint; отправленный запрос не обещается бесплатным. Жёсткое прерывание синхронного NER не заявлять без отдельного worker-process.

Приёмка: два старта одинакового запроса, одновременные разные старты, завершённый A рядом с running B, рестарт, повреждённый snapshot, traversal/symlink/чужой run_id, ошибка записи. Настоящий Model тестировать только MockTransport на вымышленном тексте; .env не читать для разработки.

## N-C1b · P0 — подтверждение списка и решения HR

1. `confirm_requirements` получает run_id/job_id/ожидаемую ревизию и явное действие. Текст/список/hash берёт из доверенного локального snapshot, заново вызывает E4.check; не доверяет payload с claimed confirmed.
2. Версия изменилась, требования не того job или snapshot повреждён → конфликт/invalid; не подтверждать новую версию автоматически. Состояние сохранено отдельно от оценки модели.
3. Подключить E8 очередь/assessment. `reviewed_for_handoff` — действие рекрутера на ревизии; финальный смысл автоматически не доказывается. Неполнота/недостоверный источник остаются видимыми и не обходятся UI-кнопкой.
4. Внутри локального запуска хранить историю: тип действия, job/requirement ids, prior/new revision, policy version, время. Не писать raw CV/ключи/полные модельные ответы в технический log. История локального однопользовательского приложения не является защищённой юридической подписью.
5. Операции review/rerender/export имеют **0 новых модельных вызовов**. Скоринг пересчитывается той же версией функции только если применено предусмотренное контрактом изменение; исходное предложение модели сохранено.

Приёмка: E4 confirmed/unconfirmed/stale/invalid, повтор операции, изменение исходника/mandatory/политики, поддельный imported report, отсутствие cross-run reuse. Полная матрица E8 и контрактные тесты Вани проходят на одном SHA.

## N-C2 · P1 — удалить один запуск и безопасно хранить результаты

Явная delete_run удаляет только принадлежащие этому run_id копии/отчёты/снимки/решения. Удаление активного запуска до остановки отклоняется; worker не создаёт данные заново после удаления. Соседний запуск, исходный файл пользователя, публичные модели и история провайдера не затрагиваются. Политика хранения: вручную до удаления, без неподтверждённого обещания TTL. Проверить delete→reopen/404, restart, symlink/traversal, частичную ошибку удаления. Точный состав удаления документировать.

## N-C3 · P0 проверки / P1 улучшение privacy

Собрать отдельный синтетический acceptance corpus поверх существующих test_privacy_real: контакты/ФИО/адреса, RU/EN ограничения, Unicode, ссылки и пары профессиональных названий в контексте навыка/компании. Егор задаёт смысл сохранённых профессиональных фактов, Codex проверяет механизм. Для каждого случая показать expected spans, найденные/пропущенные прямые идентификаторы и удалённые профессиональные фрагменты; знаменатели и режим обязательны. Это регрессионная оценка на синтетике, не recall реальных CV и не доказательство анонимности.

Сначала зафиксировать известный Rust mismatch как failing acceptance/известный предел. Исправлять только с отрицательным контролем компании/подрядчика; не добавлять общий allowlist технологий. Если безопасного исправления нет, результат остаётся явным предупреждением и пунктом ручной проверки, не скрытым unknown/fail.

Protected live — отдельный gate: после разрешения нового платного прогона на встроенной синтетике и указанного лимита. Этот ночной план не повторяет прежнее разрешение на уже потраченный $1. Реальные CV не отправлять; отсутствие разрешения не блокирует MockTransport/Docker/UI.
