## V1 — парсер, только оставшиеся проблемы

Прочитай AGENTS.md, prototype/README.md, docs/18-next-actions.md и R6/R9 в docs/reviews/full-review-2026-11-13.md. Ты не один: Codex меняет model/privacy/pipeline/scoring/CLI и сборку, Егор с Fable — contracts/evidence/requirements_review и продуктовые случаи. Не отменяй их изменения. Твои файлы: `prototype/documents.py`, `prototype/tests/test_documents.py`, синтетические fixtures и свой handoff. Общие зависимости и CLI меняет интегратор по твоему предложению.

Публичный контракт остаётся `read_document(Path) -> str`. Сверь свою готовую реализацию с обнаруженными потерями: обязательный текст в колонтитуле DOCX и во вложенной таблице сейчас может молча исчезнуть. Для каждой структуры либо сохраняй текст и порядок, либо явно отказывай безопасным кодом; не выдавай частичный текст за полный. Если твои изменения уже решают проблему, приложи тест и результат вместо повторной реализации.

Минимальные проверки настоящими библиотеками на синтетических файлах: абзацы/таблицы DOCX и порядок; колонтитул; вложенная таблица; обычный PDF и PDF без извлекаемого текста; пустой/повреждённый/слишком большой документ; неподдерживаемое расширение. Не добавляй OCR, новый API, базу или переписывание движка. Не меняй смысл статусов и скоринг. Тест должен ловить потерю нужного фрагмента или конкретный отказ, а не только отсутствие исключения.

Согласуй с Codex список безопасных кодов ошибок и действий пользователя. Не выводи сырой документ, произвольное исключение или путь с персональными данными в лог. Изменения вывода CLI и manifest делает Codex, чтобы вы не редактировали один файл одновременно. Ближайшая передача — готовая часть до 12:40 с точным остатком; новые крупные исправления после консультации.

## V2 — второй компьютер и CI

Когда появится опубликованный SHA интеграции, запусти его в отдельной чистой копии на своём компьютере. Не переключай грязную рабочую папку и не считай тест старой базы проверкой новых изменений. Установи зависимости по lock. Для автономного CLI допустим Python 3.13; для общего runtime с core целевой Python 3.12, его точный lock даст интегратор.

```sh
python -m unittest discover -s prototype/tests -v
python -m prototype demo
python -m prototype demo --scenario disputed
```

Проверь JSON/CSV/MD, маркировку replay, порядок, четыре статуса в двух примерах и сохранённые отчёты. Запиши SHA, ОС/архитектуру, Python, exit-коды, числа тестов и оставшиеся ошибки в handoff. Не публикуй приватные отчёты и ключи. К 12:40 нужен результат первой воспроизводимости или конкретный блокер.

В `.github/workflows/` добавь отдельный job для полного набора тестов CLI и двух replay по lock, без сети модели и API-ключей; существующую проверку репозитория на Python 3.13 сохрани. Далее Linux Docker build и оба offline smoke. Импортированный legacy pytest и приватный Certum в публичный CI не подключать.

После поставки C3 от Codex проверь на втором компьютере единый Docker/Compose по README, включая запуск/остановку и отказ при недоступной защите. Наш компонент защиты называется `privacy_core`, использует технологию Certum; имя внешнего пакета `certum_core` в командах не меняется. Чужое приложение Certum и личная база не нужны. Получение core/моделей и упаковку ведёт Codex. Не переносить чужие env/секреты. К 14 ноября 16:00 — проверка пакета или конкретный блокер. Платные API-вызовы самостоятельно не запускать.
