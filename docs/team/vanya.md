# Ваня: подключение и первая задача

**Следующая поставка, 13 ноября:** [готовое ТЗ V0/V1/V2](tz-vanya-2026-11-13.md). Оно начинается с публикации уже сделанного и содержит текст разрешения владельца на push отдельной ветки. Ниже — исходная инструкция первого задания.

Твоя зона — простой воспроизводимый запуск, чтение документов и удобный результат. Работай в Codex через свой ChatGPT, включая доступную тебе Astra для основной разработки. Для ограниченного поиска — Luna, для одного ревью — Sol. Эти подписочные агенты не используют продуктовый OpenAI API и его $74.

## Подключение

1. Прими доступ к приватному репозиторию под своим GitHub. Ник Вани пока не зафиксирован; при отсутствии доступа сообщи Григорию свой ник.
2. Клонируй общую базовую ветку и создай свою рабочую ветку:

```sh
git clone --branch codex/cli-recruiter-prototype https://github.com/GrigoryPislegin/hackathon-phystech-nanimai.git
cd hackathon-phystech-nanimai
git switch -c codex/vanya-documents
git clone https://github.com/obra/superpowers.git vendor/superpowers
git -C vendor/superpowers checkout 22f0b463e7a5e579904dd6211a520321035526f7
python3 scripts/setup_agents.py
```

Существующий vendor не удаляй; если он уже есть, проверь закреплённую ревизию. Если нет prototype/, клонирована старая база — сначала получи свежую ветку.

3. Открой эту папку как доверенный проект в Codex и создай новую сессию: она должна видеть `.agents/skills` и роли `.codex/agents`. Используй вход ChatGPT; для разработки API-ключ не нужен. В основной сессии выбери доступную Astra или Sol. Скрипт `bash scripts/start-agents.sh` запускает CLI на Sol и требует установленного Codex CLI.
4. Навыки: `writing-plans`, `executing-plans`, `test-driven-development`, `systematic-debugging`, `requesting-code-review`, `receiving-code-review`, `verification-before-completion`. `brainstorming` — только если требование действительно не определено. Они входят в уже закреплённые Superpowers; дополнительные плагины устанавливать не нужно.
5. Роли: `hackathon_scout` — Luna/high, ограниченный поиск без изменений; `hackathon_reviewer` — Sol/medium, одно ревью без изменений. Максимум один помощник одновременно и два запуска на задачу. Если выбранная модель недоступна — продолжи основной сессией, сообщи об этом; без платного API и цепочки замен.

## Запустить прототип

См. [точные команды](../../prototype/README.md). Для общей совместимости предпочтителен Python 3.12; CLI без Certum также проверяется на 3.13. Создай окружение, установи зависимости, запусти тесты и `python -m prototype demo`. Демо не требует ключа; это явно помеченный синтетический replay.

## Первая задача: готовый текст для Codex

> Прочитай AGENTS.md, README.md, docs/15-architecture.md, prototype/README.md. Моя зона: prototype/documents.py, отдельные тесты документов в prototype/tests/test_documents.py и инструкции запуска. Ты не один: Григорий меняет контракты, скоринг, модель, защиту и pipeline; Егор проверяет продукт. Не отменяй чужие правки. Сначала воспроизведи запуск и тесты. Затем добавь полезные проверки синтетических PDF/DOCX: текст в таблице, повреждённый файл, скан без текста, пустой документ, слишком большой документ. Найденные ошибки исправь минимально в documents.py. Никаких реальных CV, платных API, нового UI, Docker, базы и OCR-сервиса. Не меняй публичный контракт read_document(Path)->str и смысл статусов. Для отдельного поиска используй hackathon_scout; в конце один hackathon_reviewer. Готовность: одинаковые команды запуска, все проверки зелёные, ограничения форматов описаны, изменения только в своей зоне. Не коммить посторонние файлы, не пушь и не сливай без моей команды.

После первого PR следующая задача по согласованию — пакетный вход и читаемые ошибки по каждому файлу. UI начинаем только после работающего качества оценки.
