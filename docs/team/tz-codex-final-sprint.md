В отчёте явно показывать возможную потерю профессиональной информации.

## C4 · P0 — ресурсы, отказ и скорость

До первого API-вызова: проверить число/размер входов, обычные файлы без выхода через symlink, разрешённый root и пригодность out. Выдать stable job-id и локальный manifest с hash/именем; имя не уходит в модель. 21-я вакансия и плохой out не стоят ни одного модельного вызова.

Сохранение отчётов: временный каталог на том же filesystem, закрытые права, публикация rename только после полного комплекта. ENOSPC не оставляет «готовый» частичный export. UI читает опубликованные комплекты; вычислительная неполнота и ошибка экспорта различаются.

Добавить общий deadline/отмену и реальные события стадий. Разделить явные локальные output-validation errors и фатальные privacy/budget/config/network ошибки. Для первых можно продолжать другие вакансии при согласованной политике, результат остаётся incomplete; при фатальных остановить новые запросы. Сохранять успешный префикс и причину каждого неоценённого входа. Не добавлять автоматические платные повторы.

Разные лимиты Structured Output по стадиям после проверки плотных fixtures; не обрезать requirements под бюджет молча. Показать budget_limit отдельно от model_invalid, reserved отдельно от usage/расчётной стоимости, реальный остаток квоты отдельно если он не известен. Для повторных анализов — кеш требований по hash источника + model/prompt/schema/policy/context; не переиспользовать чужой tenant или устаревшее подтверждение. Смена фильтра/what-if/весов на сохранённых фактах не вызывает LLM.

Ограниченный параллелизм максимум 2 — отдельный P1 после правильных reserve/cancel/cache; тест одновременно стартующих задач не превышает общий лимит, фатальная ошибка не запускает оставшиеся. Ускорение измерить по стадиям. Время replay и микробенчмарк Егора не выдают за скорость модели.
