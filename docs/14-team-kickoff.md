## Общие правила агентов

Один основной агент на человека. Самостоятельный поиск — один небольшой помощник. В конце существенной задачи — одно независимое ревью. Не более одного помощника одновременно и двух запусков на задачу, без вложенного размножения. Исправляет основной агент. Не подключаем новых фреймворков управления агентами.

Superpowers закреплён на 7.0.2 / `22f0b463e7a5e579904dd6211a520321035526f7`. Навыки берём из одной версии; не ставим рядом второй плавающий marketplace-плагин с теми же навыками. Codex: setup_agents.py, Claude: setup_claude.py. Глобальные настройки не меняются. Никаких API-ключей для делегирования работы программистов.

Модели внутри продукта: Luna по умолчанию, Sol для сравнения. Opus используется Егором для разработки/ревью, а не добавляется третьим платным провайдером в приложение.

## Порядок до консультации

1. Общая база — ветка `codex/cli-recruiter-prototype` в приватном репозитории hackathon-phystech-nanimai. Команды в персональных инструкциях выбирают её явно; свои ветки создавать от неё.
2. Каждый создаёт свою ветку от неё и выполняет первую задачу из своей инструкции. В ветку включать только свою область.
3. Ваня проверяет запуск на другом ноутбуке. Егор с Opus проверяет правила и готовит вопросы. Григорий параллельно поднимает границу защиты и live-вызов после появления ключа.
4. За час до консультации замораживаем демо: один успешный путь и один спорный пример; результат должен быть воспроизводимым. Если live не готов, показываем честно помеченный replay, не называем его ответом модели.
5. После консультации обновляем решения и задачи по ответам; не меняем формулу молча во время параллельной работы.

## Передать результат

Формат короткой сдачи: задача → изменённые файлы → команды проверок и фактический результат → что не проверено → ссылка на PR/ветку после публикации. Григорий интегрирует после ревью и тестов. PR не сливает собственный агент автоматически. При конфликте контрактов сначала согласовать контракт, затем менять реализацию.
