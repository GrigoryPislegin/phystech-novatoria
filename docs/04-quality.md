# Качество и резерв

Проверки конкретизируются после выбора продукта. Отмечать только фактически выполненное.

| Проверка | Ожидаемый результат | Статус / доказательство |
|---|---|---|
| Чистый запуск по README | Второй участник запускает без устных инструкций | Не проверено |
| Основной сценарий | Вход превращается в полезный результат | Не проверено |
| Пустой или неверный ввод | Понятная ошибка, приложение продолжает работать | Не проверено |
| Отказ внешней зависимости | Тайм-аут, сообщение и запасной путь | Не проверено |
| Права доступа, если есть аккаунты | Пользователь не получает чужие данные | Не проверено |
| Сохранение данных, если предусмотрено | Результат не теряется после повторного открытия | Не проверено |
| Сборка / типы / линтер | Команды завершаются без ошибок | Не проверено |
| Секреты и конфигурация | Ключей нет в Git, клиенте, логах и презентации | Не проверено |
| Проверка с устройства жюри | Все обязательные ссылки открываются с нужными правами | Не проверено |

Минимум автоматизации: тест основной логики, проверки критичных ошибок и один сквозной сценарий. Для ML дополнительно — отделённая контрольная выборка и воспроизводимая метрика. Не заменять работающий показ процентом покрытия.

## Если что-то ломается

| Отказ | Подготовленный ответ |
|---|---|
| Нет интернета | Локальная версия, разрешённый пример данных и видеозапись |
| Нет доступа к API | Контролируемая ошибка; заранее сохранённый пример ответа с явной пометкой |
| Лимит ИИ | Основная логика и ручной процесс; не переключаться автоматически на платного провайдера |
| Сломалась сборка | Возврат к известной рабочей версии; не делать массовые обновления перед защитой |
| Ссылка недоступна | Проверенная резервная ссылка или архив в допустимом формате |

Накануне сдачи сохранить 60–90 секунд видеодемо, ключевые скриншоты, входные данные и команду запуска. Заглушки и запись должны быть названы заглушками и записью.
