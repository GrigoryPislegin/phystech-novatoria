# Запуск за обратным прокси

Обратный прокси завершает TLS и проверяет доступ пользователей на всех путях, включая статику, `/api/session` и `/api/runs/{id}/display-data`. Флаг приложения `--public-origin` задаёт адрес, с которого браузер открывает интерфейс. Аутентификацию обеспечивает прокси.

Пример для Docker на одном хосте с прокси. Подставьте имя опубликованного образа и внешний адрес с действующим TLS-сертификатом. Папка `/srv/recruiter/private` должна быть приватной и доступной для записи пользователю контейнера с UID 10001.

```bash
docker run --name recruiter --restart unless-stopped \
  -p 127.0.0.1:8765:8765 \
  -v /srv/recruiter/private:/app/data/private \
  recruiter:release serve --host 0.0.0.0 --port 8765 \
  --state-dir /app/data/private/local-app \
  --public-origin https://recruiter.example.test:8443
```

Прокси передаёт запросы на `http://127.0.0.1:8765`, сохраняет `Origin` и передаёт внешний `Host` вместе с нестандартным портом, например `recruiter.example.test:8443`. Указывайте origin в том виде, в каком его отправляет браузер. Для стандартного порта 443 уберите порт из флага и `Host`. Заголовки `Forwarded` и `X-Forwarded-*` не участвуют в проверке. Сохраняйте путь и метод запроса, а также заголовок `X-CSRF-Token`.

До передачи адреса пользователям проверьте, что без входа в прокси закрыты `/`, `/api/session` и `/api/runs`, а внутренний порт доступен только с хоста. После входа откройте синтетический запуск и проверьте чтение отчёта и запись решения. Приложение принимает один `Host`, сверяет `Origin` при наличии и требует токен сессии для POST и DELETE. При локальном запуске без флага используется HTTP на localhost.

Если прокси и приложение находятся в одной Compose-сети, порт приложения вообще не публикуется: прокси обращается к `app:8765`. Это исключает прямое обращение к неаутентифицированному API через порт хоста. Публикуется только loopback-порт прокси, а HTTPS-вход направляется на него. Существующие маршруты других приложений не заменяются.

Переход по ссылке из другого сайта допускается только на `GET /` с браузерными `Sec-Fetch-Mode: navigate` и `Sec-Fetch-Dest: document`. Проверки Host/Origin сохраняются; cross-site API, статика и запросы изменения по-прежнему отклоняются. Обратный прокси проверяет пароль и для этой главной страницы. Адресные HTTP-регрессии: `python -m unittest prototype.tests.test_web_app -q` — 9 PASS.
