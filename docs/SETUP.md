# Запуск и проверка

> Исторический материал о переданном Nanimai. Решение владельца от 12 ноября: новых комплектов не будет; делаем отдельный CLI. Актуальны [архитектура](15-architecture.md), [план команды](14-team-kickoff.md) и [запуск прототипа](../prototype/README.md). Запрос дополнительных архивов не является текущей задачей.

## Доступно сразу

Из корня репозитория, Python 3.13:

```sh
python3 scripts/check_repository.py
```

Это статическая проверка репозитория. Она не импортирует приложение, не обращается к модели/HH и не устанавливает зависимости.

## Platform 1.39

Источник: `services/platform`. Требуется Python 3.12; зависимости закреплены в `uv.lock`, локальный SDK находится в `dist/`. Dockerfile перечисляет системные библиотеки PDF/OCR. Команды исходного проекта после подготовки окружения:

```sh
cd services/platform
uv sync --frozen
uv run python -m nanimai_platform server
```

**Пока не проверенный рецепт полного запуска.** Нужны рабочие MongoDB, Redis, RabbitMQ и очереди, S3, Tulpa, Casino, Rocketdoc, конфигурация. Пример конфигурации неполный; секреты в примерах очищены. Текущий Compose также содержит команды `hh_worker`/`oauth2_token_worker`, которых нет в launcher. Старый README с Poetry/llm_worker не соответствует текущему launcher. Сначала закрыть задачи RUN-01 и RUN-02.

## Hharon 1.2

Источник: `services/hharon`. Python ≥3.13, PostgreSQL, Valkey, RabbitMQ и параметры HH OAuth. Требуются согласованный `config.toml`, миграции Alembic и внешняя сеть Compose. В импортированном примере порт приведён к 50054 из Compose (в исходном примере был 50051). Это не заменяет проверку совместимого dev-стенда.

```sh
cd services/hharon
uv sync --frozen
uv run python -m hharon server
```

Для исходного HR-кейса подключение HH не обязательно. Команды не выполнялись при подготовке репозитория; реальные внешние вызовы требуют отдельно настроенного тестового окружения.

## Тесты приложения

В каждом сервисе есть свои pytest-настройки и зависимости. После подготовки изолированного окружения запустить штатные тесты и записать результат в `docs/04-quality.md`. Не считать зелёную статическую CI-проверку доказательством работы интеграций или качества скоринга. Для Hharon `real_api` исключён настройками по умолчанию; не включать его случайно.

## Критерий готовности dev-стенда

Новый участник клонирует репозиторий, получает тестовый конфиг без production-доступов, выполняет описанные команды и получает результат для одной синтетической пары «вакансия + резюме». До этого статус — «запуск не подтверждён».
