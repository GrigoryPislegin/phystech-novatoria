# Собственный privacy_core — решение 13 ноября 2026

Владелец явно выбрал «Свой модуль без certum_core». Это заменяет прежнее решение брать ядро Certum. Исходный проект Certum не переименован и не изменён. Старые проверки в docs/17 и docs/23 остаются историческими; для текущего запуска не нужны их база, tenant, ключи и закрытый wheel.

## Реализация и граница

`prototype/privacy_core/` — наш код обнаружения, объединения диапазонов, ссылок одного запуска, повторной проверки и контроля жизненного цикла. Сторонние открытые библиотеки используются напрямую: [Slovnet](https://github.com/natasha/slovnet) для русскоязычных PER/ORG/LOC, [Navec](https://github.com/natasha/navec), Razdel и NumPy. Их код не выдаём за свой. Slovnet обучен на новостях, его заявленные метрики не являются качеством на резюме.

Дополнительные правила находят email, телефон, ссылки/профили, handles, некоторые форматы дат и известные поля с ФИО/адресом/датой рождения/идентификаторами. Обрабатываются Unicode NFKC и невидимые форматирующие символы. Список типов не означает полноту обнаружения. Словари исключений для названий компаний/технологий не используются.

Все тексты проходят защиту до первого обращения модели. Перед SDK и после декодирования ответа проверяются строки, включая ключи и вложенные значения. Найденный остаток или ошибка останавливают новый запрос. Модели NER обязательны; fallback без NER отсутствует. Встроенный skill-only replay остаётся отдельным явно синтетическим режимом.

Ссылки `[[PRIV:<случайный префикс>:<номер>:<тип>]]` выпускаются одним экземпляром на запуск. Исходный документ не может сам принести ссылку; ответ не может принести чужую. Для одинаковых распознанных значений в пределах запуска ссылка повторяется. Между запусками ссылки различны. Оригинальные значения не сохраняются в таблицу восстановления: в памяти индекс по HMAC с одноразовым ключом. Закрытие очищает индекс/ссылки/ключ; это управление временем жизни, не гарантия физического стирания RAM.

## Установка и повтор

Python 3.13, один lock для CLI и защиты:

```sh
.venv/bin/python -m pip install -r prototype/requirements.lock.txt
.venv/bin/python -m prototype.privacy_core.prepare
.venv/bin/python scripts/privacy_smoke.py
.venv/bin/python scripts/privacy_smoke.py --model-mock
```

`prepare` скачивает только два публичных архива с закреплёнными SHA256 и размером; это отдельная команда подготовки. При обычной обработке скачивания нет. Локальный каталог по умолчанию `data/private/privacy-models`, переопределяется `PRIVACY_MODELS_DIR`. В Docker модели находятся в `/opt/privacy-models`. Для работы модуля OpenAI-ключ не нужен. Mock smoke использует настоящий SDK, фиктивный ключ и только `httpx.MockTransport`; обращения к внешней модели отсутствуют.

В текущем Mac публичные архивы взяты из уже имеющейся копии стандартных весов и проверены по тем же хешам. Код, конфигурация и данные Certum не копировались. Docker скачивает публичные архивы заново и проверяет хеши — локальная закрытая папка не нужна другому компьютеру.

## Известные ограничения и решения

- Это псевдонимизация, не доказанная анонимизация. Редкая карьера, даты, публикации и сочетание фактов могут идентифицировать человека. Разрешение отправлять комплект кейса внешней модели не получено: эксперт отослал к техническому специалисту.
- Основной NER русскоязычный. Английские/нестандартные имена и адреса могут быть пропущены; структурные правила не превращают его в полноценный многоязычный детектор.
- Возможна потеря профессиональных данных. Например, `Rust` в «Пишу код на Go и Rust.» распознаётся как ORG, а в «Требуется знание Rust.» — нет. В отчёте есть `privacy.professional_information_may_be_hidden` при заменах ORG и предупреждение сверить локальный оригинал. Такой результат требует проверки человеком, не является доказанным отсутствием навыка. Безопасное контекстное улучшение остаётся задачей Codex; широкое исключение всех названий технологий запрещено.
- 14 ноября: `local-privacy-0.2` распознаёт явное английское представление «My name is …», включая проверенные инициалы и продолжение через `and`, без поглощения следующей профессиональной фразы. [N-C3 корпус и фактические результаты](reviews/privacy-acceptance-2026-11-14.md): 21 синтетический случай, 19/19 размеченных идентификаторов закрыты, 24/28 профессиональных фрагментов сохранены. Оставшиеся потери Rust, английского заголовка должности и полных дат опыта видны в артефактах; это не измерение полноты на реальных CV.
- Компании и города могут маскироваться; менеджеру нужны роль/сфера/период последнего места работы, а персональный работодатель при необходимости раскрывается только локально и явно. Сейчас автоматического восстановления нет.
- Синхронный NER/парсер не прерываются жёстким дедлайном. Веб-сервер должен ограничивать очередь и изолировать процесс тяжёлой обработки, если потребуется строгий SLA.
- Сохранённые отчёты всё равно могут быть чувствительными. Локальные права и удаление отчёта не заменяют политику хранения.

## Приёмка текущего среза

Синтетический корпус проверяет контакты, русские имена/компании/города, заголовок английского имени, адрес с тире/переносом, дату ISO, VK/LinkedIn, отрицание и стаж, поддельные/чужие ссылки, остаток, отказ детектора, отсутствующие/повреждённые модели и закрытую сессию. Полный список и фактические команды — docs/04-quality.md. Это не измерение recall/precision на реальных CV и не новый live-прогон.

## Если публичное хранилище недоступно

На этом Mac/в Docker 13 ноября прямая подготовка из CDN дважды закончилась TimeoutError. Проверка TLS не отключалась, хеши не ослаблялись. Для уже полученных **двух публичных архивов** есть проверяемый локальный вариант:

```sh
.venv/bin/python -m prototype.privacy_core.prepare \
  --from-dir data/private/privacy-models --dir runtime/privacy-models
docker build --build-arg PRIVACY_MODEL_SOURCE=local -t recruiter-cli:privacy-local .
```

На другом компьютере `--from-dir` указывает каталог этих же публичных архивов, полученных отдельно. Это не папка с кодом/настройками Certum. Копируются только два заданных имени после проверки размера/SHA256; Docker повторно проверяет модели. `runtime/privacy-models/` исключён из Git; build context разрешает только эти два файла. Готовый образ включает модели и работает без CDN. Default `docker build` по-прежнему использует загрузку с официальных адресов; её успешность в текущей сети не подтверждена. Проверенная сборка — вариант с локальными публичными весами.
