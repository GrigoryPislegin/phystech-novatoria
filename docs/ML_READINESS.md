# Готовность ML и скоринга

**Полного ML-комплекта пока нет.** Таблица относится к переданным архивам, а не ко всему работающему Nanimai.

| Часть | Статус |
|---|---|
| Модели вакансии, резюме, критериев и результатов | Есть в Platform |
| Извлечение PDF-текста и fallback на OCR | Код есть; сквозной запуск не проверен |
| Контракт вызова анализа, парсинга и генерации критериев | Есть: [TulpaProtocol](../services/platform/nanimai_platform/protocols/external/tulpa/protocol.py) |
| Действующий LLM/ML движок | Нет исходников Tulpa; модель и версия не установлены |
| Производственные промпты | Не установлены; три .tmpl — отдельные предоставленные материалы |
| Формула итогового балла | Есть; обычный детерминированный код, не обученная модель |
| Веса обученной модели / обучение / датасет с разметкой | В комплекте не найдены |
| Проверка качества на отложенном наборе | Не предоставлена |

## Как сейчас считается балл

[LLMService](../services/platform/nanimai_platform/services/llm/service.py) переводит full → 1, partial → 0.5, остальные статусы → 0. [ScoreCalculationService](../services/platform/nanimai_platform/services/score_calculation/service.py) вычисляет взвешенное среднее и вычитает активные штрафы `initial_weight / 100`, ограничивая результат снизу нулём. При сумме весов 0 возвращается 0.

Это балл соответствия заданным критериям, не вероятность успешного найма. Стоп-фактор сейчас является штрафом, а неизвестное соответствие может снижать балл. Для кейса МФТИ предлагаем отделить «нет данных» от установленного несоответствия и показывать цитаты.

## Что нужно получить

1. Tulpa: исходники или отдельный тестовый endpoint, согласованные API и схема результатов RabbitMQ.
2. Провайдер, точный идентификатор/версия модели, параметры, актуальные промпты, лимиты и стоимость.
3. Синтетические входы и ожидаемые результаты; отдельно разметка для независимой проверки качества.
4. Условия использования кода/модели/данных. Секреты передавать отдельным согласованным способом, не через Git.

## Обучать ли свою модель

Для первого демо обучение не является обязательным: готовая LLM может сопоставлять требования и извлекать подтверждения; качество проверяется на размеченных примерах. Следующий этап — небольшой классификатор или reranker, если сравнение покажет потребность. Дообучение LLM рассматривается только после появления устойчивой задачи, данных и baseline.

Обучающую и проверочную части разделять по исходным кандидатам/вакансиям, не только случайно по строкам. Синтетические метки модели не считать независимой экспертной оценкой. В журнале фиксировать модель, версию промпта, входной набор, параметры, качество, задержку и стоимость. Готовых результатов измерений пока нет.
