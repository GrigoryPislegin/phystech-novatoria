# Локальное приложение: запуск и приёмка

Актуально на 14 ноября 2026. Интеграционная ветка: `codex/cli-integration-consultation`.
Один рекрутер, один локальный процесс, один активный анализ. UI и CLI используют один pipeline.
Дизайн основан на переданных UI Nanimai SVG; логотип/wordmark не используются.

## Быстрый запуск из исходников

Из корня репозитория, Python 3.13:

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install -r prototype/requirements.lock.txt
.venv/bin/python -m prototype serve
```

Открыть `http://127.0.0.1:8765`. Остановка — Ctrl+C. По умолчанию API выключен, ключ не нужен, `.env` автоматически не читается.
Обычный, спорный и неполный replay доступны сразу. Для режима «защищённый mock» сначала подготовить открытые NER-модели:

```sh
.venv/bin/python -m prototype.privacy_core.prepare
```

Этот режим использует настоящий локальный privacy_core, настоящий SDK и локальный MockTransport: внешних модельных запросов **0**, ответы рукописные, режим явно показан в отчёте. Обычный replay не проверяет NER.

### Сборка из исходников

Один компонент, Compose не требуется. Docker Desktop/Engine должен быть запущен. Команды сборки и запуска одинаковы на macOS, Linux и PowerShell с Docker Desktop:

```sh
docker build -t recruiter-prototype:local .
docker run -d --name recruiter-demo -p 127.0.0.1:8765:8765 --mount type=volume,src=recruiter-data,dst=/app/data recruiter-prototype:local
```

Открыть `http://127.0.0.1:8765`. Не менять привязку порта на публичный адрес: приложение однопользовательское, без сетевой авторизации. Нативный сервер принимает только loopback; wildcard bind разрешён внутри Docker для port mapping. Процесс в образе работает как UID/GID 10001. Том хранит историю между перезапусками.

```sh
docker stop recruiter-demo
docker start recruiter-demo
docker logs recruiter-demo
```

Для обновления образа: остановить контейнер, `docker rm recruiter-demo`, пересобрать и повторить `docker run` с тем же томом. Удаление контейнера сохраняет том. Не удалять `recruiter-data`, если нужна история. Удалить отдельный анализ можно кнопкой в UI; активный сначала отменить и дождаться остановки.

Образ включает два публичных архива Slovnet/Navec с закреплёнными SHA256. Сборке нужна сеть для пакетов/весов. Если CDN недоступен, использовать **эти же проверенные публичные архивы**, без отключения защиты:

```sh
.venv/bin/python -m prototype.privacy_core.prepare --from-dir data/private/privacy-models --dir runtime/privacy-models
docker build --build-arg PRIVACY_MODEL_SOURCE=local -t recruiter-prototype:local .
```

Первая команда требует уже подготовленные архивы; она не создаёт их из ничего. Каталог runtime/privacy-models не коммитится. Allowlist Docker-контекста включает только эти два файла, код и статические ресурсы; `.env`, документы, приватные данные и certum_core не копируются. Подробности NER и лицензий — [описание privacy_core](24-local-privacy-core.md).

В release также есть `public-privacy-models.zip`: распаковка в корень репозитория создаёт `runtime/privacy-models` для локальной Docker-сборки. Штатная загрузка через CDN фактически прошла 14 ноября; подготовка двух весов заняла 1126,9 с в сети интегратора. Это замер одной попытки, не обещание времени на другой сети. Пакет образов позволяет обойти ожидание загрузки, сохраняя те же проверенные веса.

Самопроверка образа без сети и ключей, под штатным непривилегированным пользователем:

```sh
docker run --rm --network none recruiter-prototype:local demo
docker run --rm --network none recruiter-prototype:local demo --scenario disputed
docker run --rm --network none --entrypoint python recruiter-prototype:local -m unittest prototype.tests.test_run_store prototype.tests.test_local_service prototype.tests.test_web_app -q
docker run --rm --network none --entrypoint python recruiter-prototype:local scripts/privacy_smoke.py --models-dir /opt/privacy-models --model-mock
```

Для отдельной архитектуры добавить `--platform linux/amd64` или `--platform linux/arm64` при build/run. Эмуляция другой архитектуры на одном Mac не равна запуску на втором компьютере. Фактические результаты находятся в [журнале качества](04-quality.md).

## Что показать на защите

1. **Обычный пример:** «Запустить» → success → 3/3. Первая вакансия: Python/SQL, L/H=100/100. Неизвестный Java отделён от явного недостатка стажа SQL. Показать цитату требования и резюме, формулу и сравнение вакансий. Это иллюстрация политики на синтетике, не измерение качества модели.
2. **Решение HR:** подтвердить список требований первой вакансии, проверить открытые пункты, отметить для передачи. Экспорт содержит выбранную вакансию и версию решения. Повторно открыть из истории; модель не вызывается. Ручной импорт JSON всегда остаётся черновиком.
3. **Спорный пример:** составное Python/Go → partial и вопрос кандидату; недостающие данные не превращаются в отказ. Для сложных контекстных ошибок использовать E9 fixtures/проверки, не выдавая replay за реальную модель.
4. **Неполный пример:** 2/3, Java пропущен с причиной, оставшиеся результаты сохранены. Предварительное первое место не даёт права передать итог по неполному набору.
5. **Локальные документы:** PDF/DOCX/TXT/MD → проверка чтения. Содержимое разбирается в памяти; UI показывает статус/объём, имена не уходят в API. При выключенном live загруженное резюме не подставляется в synthetic replay.

## Контракт данных и решений

`application` защищает весь вход до первого вызова; `pipeline` извлекает факты+профиль, требования, оценку+условия. Профиль/условия используют существующие ответы: **1 + 2N** вызовов, без отдельных запросов для dashboard/выжимки. Некорректный профиль явно invalid и не выдаётся менеджеру как достоверный, но не уничтожает пригодный рейтинг. Некорректные условия блокируют передачу соответствующей вакансии. Цитаты проверяются структурно; смысл проверяет рекрутер.

`run_store` хранит подготовленные источники и отчёт атомарно, каталоги 700/файлы 600, проверяет хеши источников и HMAC записей. Это защита от случайной/внешней подмены JSON, **не криптографическое доказательство против владельца локального аккаунта**, имеющего ключ хранилища. Подтверждения привязаны к run_id, профилю, версии политики, источникам, требованиям и отчёту. Устаревшая ревизия → 409; повтор того же запроса с тем же ключом не вызывает повторного анализа/решения.

Решения записывает только сервис; произвольный `confirmed` внутри загруженного JSON не считается решением HR. После рестарта выполнявшийся анализ становится interrupted, автоматически платные вызовы не повторяются. Активный запуск нельзя удалить. Аварийные staging/tombstone записи восстанавливаются при старте; история соседних запусков сохраняется.

При выключенном live проверенные загрузки не сохраняются. При явно включённом live — только в памяти: максимум 20 последних наборов, срок пригодности 15 минут (очистка при следующей операции), забираются из кеша при старте. Исходные загруженные байты не записываются на диск. Закрытие сервиса освобождает кеш; сохранённые отчёты и подготовленные источники живут до удаления анализа.

HTTP: same-origin, CSRF-токен для изменений, закрытая выдача статических файлов, лимиты размера, CSP, без CORS. Это локальная рабочая станция, не многопользовательский интернет-сервис. `--allow-live` явно разрешает внешний API; ночью этот режим не запускался. Передача реальных CV требует отдельного согласования; анонимность не гарантируется простым маскированием.

## Технические критерии и оставшаяся проверка

| Критерий | Вес | Проверяемое доказательство | Что ещё не доказано |
|---|---:|---|---|
| Извлечение | 16 | DOCX/PDF/TXT/MD, строгие DTO, источники профиля/требований | Семантическая точность новой модели на независимой выборке |
| Сопоставление | 24 | 4 статуса, E3/evidence, очередь проверки, конфликт условий | Корректность сложного отрицания/пересекающихся сроков целиком |
| Ранжирование | 16 | Политика v3, группы 75/25, единицы повторов, L/H, сравнение, устойчивость лидера и решающие уточнения | Согласование весов и экспертная оценка пограничных случаев; разные формулировки не сливаются автоматически |
| Проверяемый результат | 12 | Цитаты/контекст, dashboard, версия HR, manager export | Практическое время работы рекрутера — ещё не замерено |
| Неопределённость/надёжность | 12 | partial/unknown, incomplete, cancel/restart, fail-closed privacy | Полнота обнаружения персональных данных на реальных CV |
| Воспроизводимость | 20 | Docker arm64/amd64, второй физический Mac на 48268b2, Linux CI на bffa94a, self-tests, два use case | Windows физически не проверялся; CDN на втором Mac потребовал fallback с проверенными весами |

Это карта доказательств, а не прогноз 100 баллов. E9b добавляет независимый runner размеченных синтетических случаев; результаты и пропуски надо публиковать отдельно от количества unit-тестов. HH, OCR, несколько CV, аккаунты, автоматический отказ и редактор требований не входят в текущий сценарий.
