## Смысл интерфейса

- Четыре статуса — текст/иконка вместе с цветом. Нет сведений не означает несоответствие.
- Оценка модели, проверка цитат, подтверждение состава и решение HR — разные признаки.
- «Обработано N/M», replay/mock/live, неполнота видны до прокрутки и в экспорте.
- Конфликт условий и возможная потеря профессионального текста при маскировании остаются заметны.
- Проценты/штрафы макета относятся к другой политике. Переносится компонент, значения берутся только из report. Не показывать вымышленную уверенность модели.
- Фото/имена/контакты из макета не становятся тестовыми данными кандидата; fixtures используют вымышленный текст команды.

## Поставка и проверка

Продолжать V3/V5 и их преемника; Ваня владеет static/web-report/UI tests. Pipeline/scoring/service не дублировать. Сначала один работающий экран рейтинга и анализа реального report, затем дополнительные состояния. Отдельная ветка, маленький PR, конкретные сопоставленные компоненты.

Приёмка: reference и скриншот реализации на одном viewport, обычный/спорный/неполный отчёт, список расхождений. Длинные русские строки, focus/клавиатура, 200% zoom, печать, отсутствие логотипа во всех состояниях. Pixel-diff с разным контентом не заменяет осмотр: сравнить геометрию/компоненты на фиксированной синтетике. Одного совпавшего цвета кнопки недостаточно.
