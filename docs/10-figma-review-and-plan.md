## Что описывает продукт

Основной путь из подписей схем: вход → организация → её вакансии → создание/открытие вакансии → кандидаты → резюме и анализ → вопросы и заметки → изменение этапа. Есть ручной ввод и загрузка файлов, подключение площадок и внешняя анкета. Нижняя схема дополняет путь подключением HH, проверкой баланса, конфликтом данных и настройками анализа. Её обозначение как согласованного To Be по полученным данным не подтверждено.

В макетах оценки есть вес каждого критерия, набранные баллы, процент, стоп-факторы, вывод и вопросы. В аналитике различаются «не соблюден», «частично соблюден», «полностью соблюден», «не найдено». Это полезная основа для четырёх статусов из конкурсного условия. Но на просмотренных текстовых слоях не установлена систематическая привязка каждого вывода к фрагментам обоих исходных документов.

В форме вакансии указано, что после создания нельзя добавить новый критерий/стоп-фактор, но можно изменить вес/штраф или исключить пункт. Порог автоматически распределяет кандидатов по колонкам и может быть отключён. Это поведение существующего дизайна, а не обязательное требование хакатона.

ИИ-общение описано только для откликов HH, исключает холодный поиск и PDF. После диалога предусмотрены обновление оценки и перераспределение по этапам; есть напоминания через 1, 24 и 72 часа. На хакатоне полезно переиспользовать идею уточняющих вопросов; отправка сообщений и автоматический отсев не нужны для первого сквозного результата.

Холодный поиск — самостоятельная подсистема: доступ к базе и региону, фильтры, квота скорингов, состояния кампании, интеграционные ошибки. По тексту макетов контакты на HH открываются вручную. Нельзя включать всё это в обязательный объём только потому, что экраны уже нарисованы.

Внешняя анкета — ещё один отдельный путь: редактор → публикация → заполнение кандидатом → успешный/повторный отклик. Есть пауза и прекращение доступа по старой ссылке. Для локального сравнения выданных документов этот путь не обязателен.

Числа оценок, зарплаты, имена, сроки кампаний и примеры диалогов на макетах — демонстрационное содержимое, не результаты испытаний и не подтверждённые данные кейса.

## Ключевое расхождение с условием

Доска построена вокруг **вакансии и набора кандидатов**. Полное условие, разобранное в [09-case-clarifications.md](09-case-clarifications.md), требует **одно резюме и набор вакансий с рейтингом вакансий**. Дизайн существующего продукта не заменяет ответ организаторов.

До ответа общая полезная часть — обработка пары «резюме–вакансия»: факты, требования, четыре статуса, свидетельства и вопросы. Агрегацию рейтинга и главный экран нужно проверять в выбранном направлении; простого переименования карточек недостаточно.

## Предлагаемый объём MVP

Предложение, а не принятое решение: рабочее место рекрутера с тремя основными экранами.

1. **Документы.** Одно резюме и набор вакансий; просмотр извлечённого текста и ошибки по каждому файлу. Поддерживаемые форматы согласовать по выданному комплекту.
2. **Результаты.** Рейтинг вакансий, покрытие обязательных требований, неизвестные сведения и краткое объяснение порядка. Показать ситуацию, когда ни одна позиция уверенно не подходит; правило такого вывода согласовать.
3. **Обоснование пары.** Требование вакансии → факт резюме → один из четырёх статусов → фрагменты обоих документов → объяснение → уточняющий вопрос. Из доски пригодятся структура карточки и раскрытие критериев.

Предложение для P0: извлечение, сопоставление, объяснимый рейтинг, просмотр свидетельств, ошибки, воспроизводимый запуск. Веса и формулу утвердить и зафиксировать отдельно; процент совпадения не представлять вероятностью успеха сотрудника. «Не указано» сохранять отдельным состоянием, не превращать в отрицательный факт.

Отложить до работающего P0: организации и биллинг, HH/Avito, холодные кампании, публикацию вакансий, внешние анкеты, автоматическую переписку, расширенную воронку и аналитику. Возвращать функцию в план только при доказанной пользе для критериев сдачи и наличии времени.

### Три зоны ответственности

- **Сопоставление и оценка:** схема требований/фактов, извлечение, статусы, свидетельства, формула и ранжирование.
- **Приложение и сборка:** загрузка, хранение результата, контракт с модулем оценки, ошибки, контейнерный запуск.
- **Интерфейс, проверочные примеры и демо:** три экрана, размеченные ожидаемые результаты, README/use case, сценарий защиты.

Назначение конкретных людей пока отсутствует. Контракт результата согласовать до параллельной разработки: идентификаторы документов, критерий, обязательность, статус, свидетельства с положением в исходнике, пояснение, вопрос, версия методики. Балл и покрытие сведений различать.

### Минимальная приёмка

- Все вакансии из входного набора представлены в результате либо имеют явную ошибку обработки.
- Выводы можно проверить по исходным фрагментам; система не придумывает опыт, образование и навыки.
- Нет сведений о навыке → «не указано»; явное несоответствие → отдельный статус.
- Одинаковая методика действует для всех вакансий; порядок и равные результаты объяснимы.
- Учитываются синонимы, контекст и длительность опыта; пересекающиеся периоды не складываются механически.
- Повреждённый/пустой документ и отказ модели дают понятный результат, частичные ошибки не скрываются.
- Есть минимум два use case и проверка на примерах иной структуры; синтетические примеры явно помечены.
- Решение запускается по README на другом компьютере или в чистом окружении; необходимые проверки записаны в docs/04-quality.md.
