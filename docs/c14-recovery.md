## Продолжение: безопасная замена спорного пересказа

Версия 17591b5 восстанавливала только `KNOWN_VALUE` в свободном пересказе facts. После согласованного live, выявившего такой же сбой на требованиях, преобразование расширено на все три этапа: свободные тексты фактов/профиля/требований заменяются их цитатами; пояснения оценки — исходным требованием и цитатами указанных фактов. Статусы, идентификаторы, цитаты и ссылки не меняются; отсутствующий обязательный вопрос не создаётся. Затем **весь** преобразованный ответ повторно проходит ту же privacy-проверку и контрактные проверки. Входные данные и источники не переписываются. Чужие ссылки, отказ детектора, лимит проверки и небезопасные значения в оставшихся полях по-прежнему останавливают анализ. Это удаление непроверяемого пересказа, не разрешение найденных значений. Нового запроса преобразование не добавляет; факт преобразования записывается в `model_response_normalizations`.

Синтетическая регрессия с настоящим NER и SDK MockTransport сначала воспроизвела отказ на скрытом значении в пересказе, затем дала 3/3 и 7 запросов без скрытого значения в отчёте или повторной отправке. Дополнительные проверки отклоняют восстановленную цитату, идентификатор и поддельную цитату после преобразования. Независимое ревью нашло склейку чисел из разных цитат; разделитель исправлен на ` / `, дефект воспроизведён RED→GREEN. Всего 16 проверок C14 PASS. Промпт явно запрещает угадывать содержимое защищённых меток.

Для невалидного формата, цитат или ссылок на факты добавлен **один** повтор из того же защищённого payload со статической инструкцией. Отклонённый ответ не отправляется обратно. Каждый вызов резервирует бюджет и учитывает общий deadline; privacy-ошибки и сетевые ошибки не запускают повтор. Полнота usage явно отмечена: если SDK отклонил ответ до получения usage, общий `usage_usd_estimate` равен null, известная часть хранится отдельно; резерв за оба вызова сохранён.

## Реализация и источник принципа

Прочитаны настоящие локальные исходники Certum в `~/Работа/certum-demo/vendor/certum-assistant/core`: `detectors/doc.py:is_definite`, `detectors/service.py:redact`, `detectors/vault_match.py:VaultIndex`, `gateway/model.py:request`. Detector маскирует находки; wrapper отличает структурные/известные значения от предположений NER. Очистка копии ответа для журнала в том gateway не равна защите возвращённого ответа. В нашей реализации опасный ответ отклоняется; каждый следующий payload проверяется целиком. Код Certum не копировался, зависимости/БД не добавлены.

Набор документов согласуется с HMAC-индексом скрытых значений до снимков и первого запроса. Структурные находки, восстановленные значения и чужие ссылки блокируются. Контекстная NER-находка в JSON допускается лишь при точном совпадении с защищённым источником этого запуска; ответы не расширяют доверенные источники. Общего allowlist нет; NER обязателен. Цитаты не переписываются. Диагностика содержит статические этап, направление, типы и количества без текстов и динамических JSON-путей.

Ревью выявило восстановление части замаскированного имени, Unicode/пробелы, ложное совпадение короткого имени, дорогую проверку без отмены, неверную причину остановки и двусмысленный текст неполного лидера. Исправлены; регрессии воспроизведены до исправлений. Проверка ограничена 250000 кандидатами с уступкой event loop; при превышении — явный отказ.
