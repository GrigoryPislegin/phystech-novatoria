## Как принимаем и передаём

1. Один активный этап на человека. Свою ветку пушить небольшими законченными PR; общую интеграцию обновляет Codex. Не переписывать чужие файлы параллельно и не делать force-push.
2. При старте оставить в своей задаче `TAKEN`, ветку, точный base SHA и следующий проверяемый результат. В конце — `READY`, PR/head SHA, команды и exit codes, зависимости и ограничения. При блокере — `BLOCKED`, конкретный недостающий контракт/артефакт; независимую часть продолжать.
3. Проверять свою задачу/комментарии после законченного этапа и перед следующей работой. Не делать бесконечный цикл модельного опроса GitHub каждую минуту. Новую поставку Codex проверяет и ставит следующий необходимый этап.
4. Каждая существенная поставка проходит целевое независимое ревью и необходимые тесты. После исправлений перепроверять конкретную находку. Полный suite — на интеграционной вехе; не гонять заново без изменений.
5. Stacked PR учитывать по предкам: E5 → E7; E8a → E8b; V3 → V5. Не применять повторно весь diff родительских веток. Комментарий о принятии указывает фактический интеграционный SHA; опубликованный PR сам по себе не принят.

## Порядок результата

- Рабочий сохранённый отчёт: принять viewer/export и новые модули; подключить E5 и E7 в фактический pipeline, проверить оба replay и неполный сценарий.
- Рабочее действие: реестр запусков, конкретный service adapter, E8/revision-bound решения HR, чтение/повторное открытие/экспорт без новых LLM-вызовов.
- Доставка: запуск через Docker, документированные команды и публичные веса, проверка второго компьютера/архитектуры по факту. Не выдавать один Mac за «любой компьютер».
- Визуальная приёмка: UI Nanimai по [docs/26](26-ui-nanimai-handoff.md), логотип исключён; дашборд объясняет рейтинг, диапазоны, источники, конфликты и неполноту. Модельная уверенность не выдумывается.

После каждого этапа — рабочая опубликованная версия и запись в docs/04-quality.md. Сначала эти этапы, затем улучшения по найденным провалам критериев. Новые технологии/бесконечный polish не вытесняют основной путь и приёмку. Чужие Claude/Codex запускают владельцы на своих машинах; наличие issue не означает, что агент её уже взял.
