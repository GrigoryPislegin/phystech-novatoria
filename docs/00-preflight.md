# Чек-лист до выдачи кейса

Здесь отмечаются действия команды. Наличие программы на одном Mac ещё не означает готовность всех участников.

## Люди и связь

- [ ] Известны имена, часовые пояса и доступное время всех участников.
- [ ] Назначены ответственные за продукт, сборку, данные/интеграции и защиту.
- [ ] Назначен один человек, который отправляет итоговую заявку; есть дублёр.
- [ ] Есть общий чат, канал срочной связи и правило коротких статусов.
- [ ] Заполнен templates/team.csv; у каждой задачи один владелец.
- [ ] Запланированы еда, вода, перерывы и сон для длительного формата.

## Правила и доступы

- [ ] Сохранены актуальные правила и контакты поддержки организаторов.
- [ ] Подтверждены допуск участников и лимит размера команды.
- [ ] Уточнены условия использования ИИ, готового кода, библиотек и внешних API.
- [ ] Уточнено, куда разрешено передавать данные кейса.
- [ ] Известны обязательные артефакты и способ сдачи.
- [ ] Дедлайн записан с датой и часовым поясом; напоминание в командном плане.
- [ ] У всех есть доступ к нужным аккаунтам; проверены двухфакторный вход и восстановление.
- [ ] Репозиторий доступен всем разработчикам; доступ жюри проверяется отдельно.

## Техника

- [ ] У каждого есть рабочий ноутбук и зарядка; для очного формата — переходник под экран.
- [ ] Проверены Wi-Fi и запасной интернет; известны лимиты мобильного подключения.
- [ ] Работает браузер, редактор и Git.
- [ ] После выбора стека закреплена версия runtime и сохранён lock-файл зависимостей.
- [ ] Проект запущен по README на втором компьютере.
- [ ] Есть тестовый набор данных, который разрешено использовать в демо.
- [ ] Проверены звук, камера и демонстрация экрана, если защита онлайн.

## Чего сейчас не нужно

Не нужны десятки агентов, платный модельный API для оркестрации, набор случайных фреймворков и инфраструктура без требований. Docker нужен только если кейс или выбранный способ запуска этого требуют. На этом Mac его движок на момент аудита не работал; это не мешает обычной локальной разработке.

## Вопросы организаторам — готовый список

1. Какие критерии оценки и их веса? Есть ли обязательный порог или формат результата?
2. Что должно быть реализовано в ходе соревнования? Допустимы ли шаблоны и заранее написанный код?
3. Разрешены ли ИИ-инструменты и какие ограничения действуют для передачи данных?
4. Какой точный дедлайн и часовой пояс? Разрешена ли правка ссылок после отправки?
5. Что сдаём: репозиторий, приложение, архив, презентацию, видео, отчёт?
6. Сколько времени дают на показ и вопросы? Будет ли интернет на защите?

Это заготовка вопросов, не отправленное сообщение.
