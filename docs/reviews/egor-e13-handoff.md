Путь один: fixture → настоящий OpenAI SDK на `httpx.MockTransport` → `Model.ask` → `run_pipeline` → report. Готовый отчёт вручную не пишется. Цитаты заданы по исходному тексту; харнесс переносит их на текст после защиты, как модель цитирует то, что ей показали.

## Что проходит

Без обработки защитой (`passthrough`), все четыре набора:

- 1 + 2N запросов прошли через SDK, usage записан `Model.ask`, режим отчёта — `synthetic_sdk_mock_NOT_model_output`.
- Все вакансии обработаны; цитаты и ссылки точные; профиль не `invalid`.
- Ожидания заданы до прогона как отношения: первая вакансия выше двух других, допустимые статусы ключевых строк, конфликты условий. Одного «правильного» рейтинга нет.
- **Формулировка продукта проверена тестом:** соответствие (диапазон L–H), неизвестность (доля известных данных, строки unknown расширяют диапазон) и обязательность (отдельное состояние) читаются раздельно; условия в оценку не входят.

Варианты отказов (`test_e13_failures.py`):

| Вариант | Поведение |
|---|---|
| Ответ facts отклонён | 0 вакансий, `incomplete`, все вакансии названы в `unprocessed`, профиль не выдумывается |
| Отклонена одна вакансия | остальные обработаны, счёт 2 из 3, передача заблокирована у всех |
| Цитата не из резюме | facts отклонён целиком |
| Цитата не из вакансии, ссылка на несуществующий факт | отклонена только эта вакансия |
| Посторонний факт как основание | строка спорная, в нижнюю границу не входит, `review_top` → `clarify` |
| unknown с фактом, fail без факта | вакансия отклонена |
| Цитата профиля или условия вне источника | профиль `invalid`, рейтинг цел; передача этой вакансии заблокирована |
| Поддельная ссылка защиты | с настоящей защитой отклонено на facts |

Ни в одном варианте отчёт не выглядит завершённым или отрицательным выводом.

## Что блокируется — зона Codex

С настоящим `privacy_core` 0.3 (код ветки, NER из образа) **все четыре набора останавливаются на facts: `privacy_residual_findings`, 0 вакансий.** Это тот же отказ, что в живом запуске владельца, теперь на синтетике. Тесты фиксируют его как skip с причиной; проверки не отключены. Когда защита будет исправлена, эти тесты начнут проходить сами; любой третий результат — падение.

1. **P0. Проверка ответа отклоняет профессиональные термины.** На минимальном наборе блокируется слово «SQL», стоящее отдельно: текст и цитата пункта стека, свободный текст факта. В самом CV «SQL» внутри предложения не маскируется, то есть модель обязана его процитировать. Если убрать термины из свободных полей, facts проходит, но блокируется уже **исходящий** запрос evaluation: названия инструментов в полях требований.
2. **P0. Утечка.** В минимальном наборе строка с вымышленными фамилией, именем и отчеством не замаскирована и уходит в запрос facts. В трёх больших наборах имя замаскировано.
3. **P1. Потеря профессиональных сведений.** В трёх CV по два-три названия организаций, а замен ORG — 11, 12 и 17: остальное — инструменты.
4. **P1. Ошибка защиты на одной вакансии останавливает остальные.** Любой код, кроме `model_invalid`, прерывает цикл: вакансии после отказавшей не запрашиваются.

## Ограничения

- Настоящая защита проверялась в контейнере образа `bffa94a` с подмонтированным кодом ветки: в локальном окружении нет библиотек NER.
- Ответы рукописные: тесты не говорят, как поведёт себя модель на таких документах.
- Различие unknown и fail структурно не проверяется, если модель приложит посторонний факт к fail: это решают модель и рекрутер, читающий цитату (тест `test_silence_widens_the_range…`).
- Вес и версия политики не менялись.
