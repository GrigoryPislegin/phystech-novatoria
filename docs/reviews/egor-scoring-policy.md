13 ноября 2026, Егор. Задача #7, E5. База — `codex/cli-integration-consultation` (`ea1369f`).

Политика одна на весь набор вакансий. Число — оценка по этой политике, а не вероятность найма и не единственно верный рейтинг. Ниже для каждого правила указан источник:

- **Эксперт** — ответ эксперта по [docs/12](../12-expert-answers.md);
- **Команда** — наше решение, его можно заменить;
- **Открыто** — вопрос не решён, в коде стоит осторожный вариант.

Эта поставка — схема и fixtures. Расчёт по разделам 4–8 в `scoring.py` будет следующим PR. Сейчас код считает по `draft-2026-11-12-v1` с интеграционным фильтром Codex.

## 2. Границы оценки

Для вакансии с весами `w` и статусами строк:

- `P` — сумма `w·value` по строкам, засчитанным в L (раздел 4);
- `K` — сумма весов этих строк;
- `W` — сумма всех весов;
- `L = 100·P/W` — нижняя граница;
- `H = 100·(P + W − K)/W` — верхняя граница: всё незасчитанное считается подтверждённым;
- `coverage = 100·K/W`.

**Монотонность.** При прочих равных усиление статуса строки (`fail → partial → full`) не уменьшает L. Строка, переведённая в спорные, не уменьшает H.

## 3. Обязательные требования

| Правило | Источник |
|---|---|
| Обязательность берётся из цитаты вакансии и проверяется структурно (`check_mandatory`) | Команда |
| Только `MandatoryCheck.state = structure_ok` даёт вес 3 и участвует в группе обязательных | Команда. Это интеграционный фильтр Codex, теперь часть политики |
| `needs_review` по обязательности: вес 1, исходная цитата сохраняется в `score_review.excluded_mandatory_ids` | Команда |
| `fail` по обязательному не компенсируется другими требованиями: такая вакансия ниже всех вакансий без нарушения | Команда (v1). Открыто: эксперт компенсацию не обсуждал |
| Стаж 1 год вместо 3 — это `fail`. Отказ решает рекрутер | Открыто: вопрос эксперту остаётся |

Регрессия: «Обязательно: SQL. Python желателен.» при маркере, привязанном к Python, не делает вакансию `violated` (`test_unbound_mandatory_cannot_demote_job_to_violated`).

## 4. Спорные доказательства

Строка засчитывается в L и `coverage` только при `RowCheck.state = structure_ok`.

| Состояние E3 | L | H | Группа обязательных |
|---|---|---|---|
| `structure_ok` | по статусу модели | по статусу | `fail` → `violated`, иначе как в v1 |
| `needs_review` | 0 | полный вес | спорный `fail` → `clarify`, не `violated`; спорный `full` не даёт `confirmed` |
| `no_evidence` (`unknown`) | 0 | полный вес | `clarify` |
| `invalid` | вакансия получает ошибку `invalid_evidence` и в рейтинг не входит | | |

- Статус модели не переписывается. Строка хранит исходный статус и причины, а в `score_review.disputed_ids` попадает её id.
- «Не работал с Python» + цитата «Python» + `full`: строка получает `quote_is_fragment` и `needs_review`, в L она не идёт. Рекрутер видит предложение целиком и заголовок.
- Ошибка извлечения не становится `unknown`: `invalid` — это отдельный результат вакансии.
- Общее слово доказательством не считается. Связь по термину только отправляет строку на проверку (`evidence_not_linked`) и ничего не подтверждает.

Источник: Команда. Почему так: незасчитанная строка двигает только L, и проверка рекрутером может лишь поднять оценку. Ни один спорный вывод не попадает в L молча.

## 5. Составные требования, дубли, стаж

| Случай | Правило | Источник |
|---|---|---|
| «Python и Go» | Модель делит на два требования с одной цитатой и разным `text`. У каждого своя обязательность (заголовок покрывает оба). Если не разделено, то `full` только когда подтверждены все части, `partial` — когда подтверждена часть | Команда |

| Пересекающийся стаж | Стаж параллельных мест не складывается. Если по датам пересечение не исключить, то `partial` с вопросом, а не `full` по сумме | Команда, правило для SYSTEM |
| «Изучал», «курсы» | Это не опыт работы. Для требования стажа — `fail` или `partial` с вопросом, не `full` | Команда, правило для SYSTEM; E6 |

## 6. Факторы эксперта

Эксперт назвал факторы: стек, релевантный опыт, сфера, условия. DTO `RequirementFactors` в `contracts.py`:

```python
Factor = Literal['stack', 'relevant_experience', 'domain', 'conditions', 'other']
RequirementFactors(items=[RequirementFactor(requirement_id='r1', factor='stack'), ...])
```

- Категорию предлагает модель, и она не проверена. **В v2 вес от категории не зависит**, поэтому ошибочная категория не меняет L, H и место.
- Категория нужна для группировки в отчёте («по стеку 2 из 3 подтверждены») и для E7.
- Требование без записи получает `other`, отчёт без DTO — все `other`. Это обратная совместимость: `Requirement` не менялся, fixtures мигрировать не нужно.
- Веса по факторам — **Открыто**. Подбирать их под отдельные вакансии нельзя.

## 7. Условия работы

`candidate_profile.Conditions` сравнивает режим, место, график, релокацию и зарплату CV ↔ вакансия.

| Состояние | Когда |
|---|---|
| `compatible` / `conflict` | Обе стороны сказаны явно, у каждой есть цитата |
| `unknown` | Хотя бы одна сторона не указана. `unknown` с цитатами обеих сторон уходит на проверку (`unknown_with_both_sides`): модель могла не заметить конфликт |

- Конфликт показывается HR и в оценку не входит (Эксперт). Автоматического отказа нет.
- Зарплата с `compatible` или `conflict` всегда уходит на проверку: валюта, период и налог не угадываются.
- Город и период не достраиваются: если в цитате нет данных, состояние `unknown`.
- Это сравнение двух документов, а не интервью с кандидатом.

## 8. Рекомендация и запрет полного вывода

| Рекомендация | Условие |
|---|---|
| `incomplete` | Обработаны не все вакансии |
| `review_none_fit` | Все вакансии `violated` по строкам `structure_ok`. Спорный `fail` не считается |
| `clarify` | У первого места есть `clarify`, спорная строка или `L = 0` |
| `review_top` | Иначе. Это всё равно «проверьте первое место», а не окончательный вывод |

Итог «полностью подходит» запрещён при неполном наборе, неподтверждённом списке требований (E4), спорной обязательной строке или непроверенной обязательности. Пока в CLI нет ручного подтверждения, `verification.final_allowed` всегда `false`.

## 9. Профиль кандидата

Схема — `candidate_profile.CandidateProfile`. Эксперт назвал состав выжимки: общая информация, стек, последнее место, достижения.

```python
CandidateProfile(summary=[Claim], stack=[Claim], last_position=LastPosition | None,
                 achievements=[Achievement], missing=['last_position', ...])
Claim(text, sources=[ClaimSource(fact_id, quote)])     # quote — фрагмент цитаты факта
LastPosition(role: Claim, domain: Claim | None, period: Claim)
Achievement(action: Claim, result: Claim | None)
```

`check_profile(profile, facts, cv)` → `structure_ok | needs_review | invalid`.

| Проверка | Код | Тяжесть |
|---|---|---|
| `fact_id` не существует | `unknown_fact_id` | invalid |
| Цитата не входит в цитату факта | `quote_not_in_fact` | invalid |
| В тексте утверждения есть цифра, которой нет ни в одной цитате | `number_not_in_source` | invalid |
| Раздел пуст, но не указан в `missing`, или наоборот | `missing_mismatch` | invalid |
| В периоде последнего места нет года («2000 пользователей» — не год) | `undated_last_position` | invalid |
| Период взят из другого факта, чем роль | `period_not_bound_to_role` | invalid |
| В тексте резюме (не только в фактах) есть год позже периода | `later_period_in_cv` | review |
| Цитата факта стоит в разных контекстах резюме | `ambiguous_location` | review |

- Персональных полей нет: имени, контактов, возраста, работодателя. Тест фиксирует набор полей.
- `ProfileCheck.display` даёт то, что показывает отчёт: `Claim.text`, если он входит в цитату, иначе сами цитаты, как `display_label` для требований. Перефраз без цифр («ведущий разработчик в крупном банке», «ускорил вчетверо») проверка не ловит. Поэтому он и не показывается.
- Схема не вызывается из pipeline (`INTEGRATED = False`), поэтому работающей функцией её называть нельзя.

## 10. Инварианты для приёмки

Проверяются в следующем PR вместе с расчётом:

1. Обычный и спорный replay дают прежние места и рекомендации.
2. Перестановка вакансий, требований, фактов и переименование id не меняют L, H, места и рекомендацию.
3. `unknown` никогда не даёт `violated`.
4. Усиление статуса строки при прочих равных не уменьшает L.
5. Спорная строка не входит в L, и её `fail` не создаёт `violated`.
6. Категория фактора не меняет оценку.
7. Конфликт условий не меняет оценку и место.
8. Профиль: 0 утверждений без источника; без дат нет последнего места.

## 12. Изменения для Codex

Схема и проверки готовы, подключение — после согласования.

1. **Модель.** Новые задачи `profile` (`CandidateProfile`), `conditions` (`Conditions`), `factors` (`RequirementFactors`). Все поля обязательные, без значений по умолчанию, лишние поля запрещены. Тест проверяет это по JSON Schema pydantic; строгое преобразование OpenAI SDK не запускалось.
2. **SYSTEM:**
   - «profile: каждое утверждение ссылается на fact_id и дословный фрагмент цитаты этого факта; не пиши чисел, которых нет в цитате; работодателя и личные данные не указывай; последнее место — только при датах в резюме, иначе null и last_position в missing»;
   - «conditions: compatible/conflict только при явных данных в обоих документах, иначе unknown; не угадывай валюту, период, город»;
   - «requirements: составное требование раздели на отдельные; стаж параллельных мест не складывай; обучение и курсы — не опыт работы».
3. **pipeline.** `check_profile(profile, facts, Source.of('cv', safe_resume))` один раз на запуск. `check_conditions(conditions, facts, cv, Source.of(jid, text))` на вакансию. Результаты — `report.profile`, `job.conditions`. При `invalid` раздел показывается как «не удалось проверить», а не пустым.
4. **scoring.** Следующий PR Егора: разделы 4 и 8, `score_review.disputed_ids`, `policy_version = draft-2026-11-13-v2`.

## Что код не ловит

- Смысл цитаты целого предложения: структура «Не работал с Python» как целое предложение + `full` пройдёт. Смысл всегда помечен как утверждение модели.
- Стек из перечня: «Python» из «Не работал с Python» как пункт стека пройдёт структурно. Отчёт должен показывать предложение-источник у каждого пункта (`spans`), P2 фиксирует запрет для E6.
- Перефраз без цифр: «руководил командой» из «участвовал в команде». Поэтому `display` показывает цитату, а не `text`.
- Если цитата встречается внутри одной цитаты факта дважды, берётся первое вхождение.
- Совпадение сферы («онлайн-обучение» ↔ «образовательная платформа») — вывод модели.
