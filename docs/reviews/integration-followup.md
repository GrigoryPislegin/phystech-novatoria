# Разбор ревью Егора — 13 ноября 2026

Источник: PR https://github.com/GrigoryPislegin/hackathon-phystech-nanimai/pull/2, head b6aeff41bb5358666f3031289268b1a9a6a2ae3d. Три исходных файла Егора импортированы без правок; PR не сливался. Работа продолжается в codex/cli-integration-consultation; чужие локальные изменения сохранены.

План этого изменения: воспроизвести находки → добавить регрессии → исправить контракт/отчёт/стадии ошибок → подготовить упаковку CLI → независимое ревью → записать проверки. Предметный контракт задают docs/12-expert-answers.md и docs/15-architecture.md.

| Находка | Решение / статус |
|---|---|
| 1. Чужая обязательность | mandatory_quote должна включать quote целиком, минимум 8 символов. Общая цитата «Python и SQL обязательны» допускается для двух разных требований. Смысл обязательности всё ещё проверяет человек. |
| 2. Слово вместо доказательства | Открыто. Нельзя обещать решение семантики проверкой длины или регулярным выражением. Нужны контекст факта, проверка отрицаний/релевантности и отдельная оценка качества; демонстрация остаётся replay. |
| 3. Ранжирование по L | Формула сохранена до решения эксперта. Показать на консультации подробную/короткую вакансию и unknown против fail. |
| 4. Отчёт | Конкретные сильные стороны, partial, несоответствия и неизвестное; первые вакансии и действие рекрутера; обязательные цитаты и сводка чисел по местам. |
| 5. Ошибки | Стадии запроса/валидации, список неоценённых; ошибка facts даёт пустой incomplete-отчёт без невалидных фактов. Первичная privacy-ошибка по-прежнему блокирует вызовы без отчёта. |
| Доп. точный дубль | Повтор text+quote отклоняется. Семантические дубли не гарантированы. |

Решение о порядке работ: сначала пункты 1/4/5 и воспроизводимость, затем смысловые изменения после консультации — это сохраняет черновую формулу команды, но оставляет риск ложных full/fail в live. Автоматические кадровые решения недопустимы.

Dockerfile — отдельный автономный CLI на Python 3.13. Он не решает упаковку Certum: core требует отдельного Python 3.12, моделей и PostgreSQL. Build context ограничен каталогом prototype; .env и пользовательские данные исключены. Побайтовая воспроизводимость базового образа не заявлена. Docker smoke пока заблокирован окружением, не заменяется обычными unittest.

Проверки и результаты — в docs/04-quality.md. Сроки — в docs/16-work-gantt.md.

Независимое ревью нашло остаточный случай п. 1: длинная mandatory_quote от заголовка «Обязательные требования» через раздел «Желательно» до SQL проходит проверку вложения. Фикс отклоняет исходные примеры чужих/односимвольных цитат, но НЕ закрывает смысловую обязательность полностью. До подтверждения рекрутером это остаётся известным риском; не менять смысловую политику по ненадёжной эвристике заголовков.

Два найденных ревьюером дефекта исправлены: действие clarify при всех необязательных fail больше не ссылается на отсутствующие unknown/partial; Docker использует явные COPY и исключает содержимое вновь разрешённых директорий перед точечным включением файлов. Первоначальная статическая проверка .dockerignore была недостаточной: реальный образ показал лишние файлы, повторная проверка после исправления подтвердила точный список. Уточнены проверки минимальной длины цитаты и остановки вызовов. Отдельный сводный блок вопросов кандидату отложен: вопросы сейчас есть у каждого требования.
