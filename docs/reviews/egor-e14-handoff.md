# E14 — полезный скоринг: настоящие совпадения считаются, выдуманные нет

14 ноября 2026, Егор / Fable. Задача #42. База `a289b03` (`codex/c14-safe-mvp`). Файлы privacy, model, pipeline, application и static не менялись. Синтетика; качество Luna не измеряется; платных прогонов не было.

## Этап 1. Главный дефект: «1 full + 7 unknown → покрытие 0, интервал 0–100»

**Причина.** Строка была предложением модели с точной цитатой, но структурная проверка отправляла на проверку любую цитату, которая является частью предложения, пунктом списка или двумя предложениями. Это три обычных способа процитировать навык («Навыки: Vue.js, TypeScript» → «Vue.js»). Спорная строка не входит ни в нижнюю границу, ни в покрытие — отсюда 0 и 0–100.

**Разница понятий.** «Предложено моделью» — статус строки с цитатой. «Пригодно для расчёта» — та же строка, если структура цитаты не оставляет места другому смыслу. Только вторые входят в нижнюю границу.

**Исправление** (`evidence.py`, правила `evidence-0.2`). Цитата уходит на проверку, только когда есть конкретный риск:

| Ситуация | Было | Стало |
|---|---|---|
| Часть нейтрального предложения, пункт под нейтральным заголовком, целые предложения | спорно | считается |
| В опущенной части предложения есть отрицание, намерение, учёба или низкий уровень («не работал», «планирую», «курс», «только», «базовый») | спорно | спорно |
| Заголовок списка с такой оговоркой («Не работал с:») | спорно | спорно |
| Посторонний факт без общего термина | спорно | спорно |
| Одинаковая маска в резюме и вакансии | считалось связью через служебные слова маски | связь по самому значению |
| Разные маски | считалось связью (ошибка) | спорно, код `link_hidden_by_mask` |
| Термин скрыт только с одной стороны | спорно без объяснения | спорно, «сверьте с исходным документом» |

Список оговорок намеренно широкий: срабатывание лишь отправляет строку рекрутеру.

**Версии.** Формула и веса v3 не менялись, `policy_version` прежняя (UI привязан к этой строке). Новые проверки помечены `evidence_check.rules_version = "evidence-0.2"`; у сохранённых отчётов поля нет, их расчёт воспроизводится по сохранённым состояниям.

## Новые поля (аддитивно)

- `score.shares` — три доли шкалы: `confirmed` (то же число, что `coverage`), `disputed` (утверждения модели, ждущие сверки цитаты), `unknown` (в резюме ничего нет). В сумме 100.
- `score.breakdown` — id строк по рубрикам: `full`, `partial`, `fail`, `unknown`, `disputed` и отдельно `stop_factors` (подтверждённый fail применённого обязательного).
- `ranking.leader.comparable` — `false`, когда ни по одной вакансии нет засчитанных совпадений: лидера нет, `leader.summary` начинается с «Недостаточно данных для сравнения». Состояние остаётся `open` с причиной `no_confirmed_fit`.
- `evidence_check.rules_version`, код причины `link_hidden_by_mask`.

Для Вани: показывать `shares.disputed` как «предложено моделью, требует сверки», а не как отсутствие данных; при `comparable = false` не рисовать лидера.

## Этап 2. Сохранность смысла и оси компетенций

**Падающие регрессии** (`test_e14_professional_fidelity.py`, настоящий NER; без NER модуль пропускается, с NER дефект — FAIL, не skip). На `local-privacy-0.5`: 3 PASS, 6 FAIL.

- PASS: 3 из 3 вакансий обработаны; заданные вымышленные ФИО, телефон и email в запросы не попали; засчитанные основания читаемы.
- FAIL: профессиональные фрагменты — 28 из 37 (потеряны `SQL`, `Git`, `Figma` в перечислении, `PostgreSQL`, `Kafka`, `Power BI`, `Tableau`, `МСФО`, глагол «Сократил»).
- FAIL: сквозной прогон даёт 3/3 ценой смысла — до модели доходит 12 терминов резюме из 17; два разных требования стали одной строкой «Опыт работы с ▮.».
- FAIL: роль под строкой с ФИО и инструмент рядом с работодателем маскируются.
- FAIL: утечка — улица и дом в строке адреса.

**Оси компетенций** — `competency_axes(job, labels)` в `ranking_explanation.py`. Оси: инструменты и технологии, профильный опыт и стаж, сфера, образование, руководство, языки. Вес оси — сумма весов её требований по политике v3 (сумма 100), поэтому повторы и необязательные строки сдвигают ось ровно как оценку. Значение оси — только засчитанные основания; без них точка не рисуется (`score = null`). Меньше четырёх осей или данные меньше чем по трём — `radar_ready = false` и короткая честная сводка.

Пример (вымышленный аналитик, вакансия an-1): опыт — вес 30, оценка 100; инструменты — 51,25, 100; сфера — 6,25, 0; языки и руководство — по 6,25, 100. Сводка: «Подтверждено 100 п. из 100… Сильнее всего: инструменты и технологии».

**Нужен контракт (не реализован в wire):** группа компетенции у требования. Предложение: в ответ `requirements` добавить `factors: [{requirement_id, factor}]` — уже существующий DTO `RequirementFactors`, значения `stack | relevant_experience | domain | education | management | language | conditions | other`; без дополнительного вызова модели. В отчёт: `job.requirement_factors`. Пока поля нет, `competency_axes` возвращает `reason = "no_labels"` и сводку.

**Приёмочные отношения** (`test_e14_acceptance_relations.py`): четыре статуса ключевого требования дают четыре разных результата; подтверждённый опыт поднимает; доказанный провал обязательного опускает ниже любой вакансии без него; повторы и необязательные строки не переворачивают порядок; одно ключевое unknown даёт один точный вопрос; «почему выше» ссылается на существующие цитаты; неподтверждённый список требований — состояние процесса, не ноль.

## Вердикт

Рекрутеру можно показывать: порядок, три доли (подтверждено / ждёт сверки / нет сведений), рубрики строк, стоп-факторы, решающий вопрос, «недостаточно данных». Мешает: защита скрывает инструменты, поэтому часть совпадений уходит в «сверьте с исходным документом»; оси требуют меток от модели.

## Границы

- Синонимы и перевод («реляционные СУБД» ↔ название базы) без общего слова остаются спорными: связь лексическая.
- Ограничение уровня без слова из списка («уверенно читаю чужой код») не ловится.
- Метки осей — предложение модели, как и статусы; ошибочная метка сдвигает ось, но не оценку.
