# V4. Чтение документов и диагностика

Запустите из корня репозитория в окружении прототипа.

```bash
python -m prototype.documents -- ./resume.docx ./vacancy-1.pdf ./vacancy-2.docx
```

Проверка идёт локально по всем перечисленным файлам. В JSON поле `file` — номер
файла в порядке аргументов, начиная с 1. При успехе выводятся `status: ok` и
число извлечённых символов. При ошибке выводятся `status: error`, `code`,
`reason` и `action`. Код завершения 0 означает, что все файлы прочитались, 2 —
что хотя бы один файл надо исправить. Имена, пути и текст файлов в вывод не
попадают. Проверка читает документы без запуска анализа вакансий.

## Поддержка форматов

- DOCX. Абзацы, таблицы и вложенные таблицы читаются в порядке основного текста.
  Переносы и табуляция внутри абзацев сохраняются. Между ячейками ставится
  ` | `, объединённая ячейка читается один раз. Документы с текстом в
  колонтитулах, текстовых полях и фигурах Word отклоняются с отдельными кодами.
  Текст внутри элементов управления содержимым, формул или отслеживаемых
  вставок, ссылки на сноски, вставленные фрагменты, диаграммы Word, SmartArt
  и специальные символы Word вроде отметок Wingdings дают
  `docx_unsupported_structure`. Изображения и их оформление остаются за
  пределами извлечения.
- PDF. Читается текстовый слой в порядке страниц. Документ отклоняется целиком,
  если хотя бы одна страница пустая или без извлекаемого текста. OCR и
  восстановление визуального порядка колонок в PDF не предусмотрены.
- TXT и MD. Читаются в UTF-8, в том числе с BOM. Переносы строк приводятся к LF.

Максимум 5 000 000 байт на файл, 100 страниц на PDF, 20 000 000 байт данных
DOCX по ZIP-оглавлению и 60 000 символов после извлечения. Парсер синхронный.
Пределы размера не задают максимальную длительность обработки.

## Подключение в CLI и веб-транспорте

`read_document(Path) -> str` возвращает текст либо поднимает
`DocumentReadError`, подкласс `ValueError`. Общая функция
`document_diagnostic(error)` преобразует эту ошибку и известные ошибки входной
проверки `application.load_documents` в безопасные поля `code`, `reason`
и `action`. Для локальной проверки списка транспорт может использовать
`inspect_documents(paths)` и сопоставить поле `file` со своим списком файлов.
Веб-транспорт передаёт только собственные локальные пути из текущей загрузки,
связанные с её идентификаторами.

Интегратору CLI нужно использовать `document_diagnostic(error)` на границе
чтения входных документов, где известна позиция файла. В этом PR подробный
вывод доступен через `python -m prototype.documents`. Команды
`python -m prototype run` и `inspect` выводят ошибки по текущим правилам
CLI. В `run` общая проверка числа файлов и символических ссылок остаётся
в `application.load_documents` и идёт до чтения. При 20 вакансиях читатель
получает 21 вызов вместе с резюме, при 21 вакансии — 0. Проверка списка файлов
сама по себе не проверяет число вакансий.
