# Печатный отчёт для менеджера

Откройте `prototype/static/index.html` в браузере, выберите `report.json` и
нужную вакансию. Кнопка «Отчёт для менеджера» скачает
`nanimai-manager-report.html`. В скачанном файле нажмите «Печать / PDF» и
выберите принтер или «Сохранить как PDF». Для PDF без пути к файлу отключите
колонтитулы в диалоге браузера. Экспорт работает офлайн, в том числе из
локального файла `index.html`.

Сверху — вывод по выбранной вакансии и его причины, краткий профиль и условия
для HR. В профиле видны специализация, опыт, стек, последняя роль со сферой и
периодом, достижения и указанные результаты. Ссылки ведут к цитатам из резюме
и вакансии внутри HTML. В отчёте видны все требования выбранной вакансии,
включая скрытые фильтрами экрана, и до пяти вопросов по имеющимся пробелам.
В неполном запуске число оценённых вакансий и предварительность места стоят вверху.

## Данные отчёта

- Печать использует тот же проверенный набор строк и цитат, что и экран.
  Оценка соответствия, проверка доказательства и подтверждение списка
  требований показаны отдельно. Отчёт версии 0.1 остаётся черновиком для
  рекрутера. Пробел в резюме отображается как «Сведения не указаны».
- Основания и вопросы строятся по строкам оценки. Свободные комментарии и
  вопросы модели из старого формата остаются на экране с отметкой «не проверен».
  Строка без структурной сверки цитат доступна для проверки в подробностях.
  Для реальных вакансий показывается номер в списке, а идентификатор,
  вычисленный из исходного текста, используется внутри экрана для выбора.
  Локальный манифест и поля с именами входных файлов в HTML не переносятся.
- Цитаты переносятся как текст из входного отчёта. Для передачи менеджеру
  проверьте, что в самих цитатах нет личных сведений. Экспорт не выполняет
  дополнительную маскировку.
- Сохраняются режим запуска, версия отчёта, модель, версия методики и
  SHA-256 обработанных текстов, если движок записал их в JSON. SHA-256 модели и
  методики отображаются при наличии в `model_sha256` и `score.policy_sha256`.
  Текущие синтетические отчёты содержат версию методики и хеши источников.
- Вывод по вакансии строится из её строк оценки. Для соответствия по всем
  оценённым требованиям нужны полный запуск, подтверждённый список требований,
  отсутствие спорной обязательности и структурно сверенные цитаты. Остальные
  состояния различают несоответствие, частичное соответствие, недостаток сведений
  и необходимость сверки. Окончательное решение остаётся за рекрутером.
- Дополнительные данные поступают в `report.profile` (`ProfileCheck` из E5)
  и `ranking.jobs[].conditions` (`ConditionsCheck` из E5). Используются
  привязанные к хешам обработанных текстов цитаты. Профиль показывает цитаты в
  контексте предложения и заголовка. В условиях обе стороны видны рядом,
  возможный конфликт выделен для HR. Если одна сторона молчит, условие требует
  уточнения. Зарплата всегда требует ручной сверки. Условия не меняют рейтинг.
- Пока интегратор не подключил E5, обычный запуск заполняет только вывод по
  вакансии. Профиль и условия отображаются, когда проверенные поля есть во
  входном JSON. Сохранённые отчёты без E5 открываются с явной отметкой о том,
  что профиль не извлечён и условия не сравнивались.

## Воспроизвести проверку

Сгенерируйте новые синтетические примеры командами из корня проекта в окружении
прототипа. Для неполного запуска откройте
`prototype/tests/fixtures/web/incomplete.json`.

```sh
python -m prototype demo --scenario success
python -m prototype demo --scenario disputed
node --test prototype/tests/test_web_report.cjs prototype/tests/test_web_manager.cjs
```

В `success` по первой вакансии должны быть два основания. В `disputed`
откройте первую вакансию и сверьте частичное соответствие, цитату о Python и
вопрос по составному требованию. Затем выберите вторую вакансию и проверьте,
что в скачанном HTML указан `job-002` и отображается «Сведения не указаны».

Для проверки по замечаниям жюри откройте
`prototype/tests/fixtures/web/manager-profile.json`. Это вымышленный профиль
на основе примера P1 Егора, проверенный локальными функциями `check_profile`
и `check_conditions` из PR №8 (коммит `dd5862c`). У `job-001` частичное
соответствие по стажу Python, совпадение по Django, офис в вакансии и только
удалённая работа в резюме. У `job-002` сведений о Java недостаточно, а условия
по формату работы совпадают. Смена вакансии меняет вывод и условия, профиль
продолжает относиться к одному резюме.
