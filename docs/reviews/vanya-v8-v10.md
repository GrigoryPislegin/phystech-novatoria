# Приёмка V8–V10

Интеграционная база `467cd60`. Работа выполнена в `codex/vanya-v8-v10`.
Для воспроизведения используется одно приложение и один pipeline. Релиз
`night-bffa94a` относится к более раннему коду.

## V8. Запуск из браузера

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install -r prototype/requirements.lock.txt
.venv/bin/python -m prototype.privacy_core.prepare
.venv/bin/python -m prototype serve
```

Откройте `http://127.0.0.1:8765` и выберите «Документы». Проверка показывает
имя, роль и результат каждого файла. При ошибке указывает причину и действие.
Имена отображаются в браузере. По HTTP передаются только файлы выбранного
набора, а в модель идут только тексты после локальной защиты.

Одно резюме и до 20 вакансий. До 5 МБ на файл. Суммарный предел файлов —
18,7 МБ. Он оставляет место для base64 и метаданных при жёстком ограничении
тела запроса 25 МБ. Форматы DOCX, PDF с текстовым слоем, TXT и MD. OCR
отсутствует. Лимиты для отдельных форматов описаны в [приёмке V4](vanya-v4-documents.md).

- «Запуски» → «Синтетический replay» или «Защищённый Mock SDK» использует
  встроенный пример, явно подписанный в отчёте.
- Загрузка точного вымышленного набора `prototype.demo.demo_inputs()` для
  сценария `success` или `disputed` открывает отдельную кнопку «Запустить
  локальный Mock SDK». Для неё работают реальный парсер, NER и SDK с локальным
  транспортом. Внешних модельных запросов 0. Обычный пользовательский
  документ проходит локальную проверку чтения.
- Внешний анализ доступен только при явно запущенном `serve --allow-live`,
  настройке ключа на сервере и отдельном подтверждении в интерфейсе. Сумма
  резерва ограничена $1. Повтор отправки после потерянного ответа пользуется
  тем же idempotency key. Отмена останавливает следующие обращения, уже
  отправленный запрос может быть оплачен.
- После «Открыть отчёт» адрес содержит `?run=<id>`. Перезагрузка повторно
  открывает опубликованный отчёт. Сбой чтения сохраняет предыдущий вид и
  объясняет ошибку. Сохранённые запуски принадлежат этой локальной рабочей
  станции.

В CLI `prototype inspect` и `prototype run` возвращают код 2 и JSON с
`code`, `reason`, `action` при отказе файла. Для `run` указаны роль и номер
вакансии в порядке имён входных файлов. Путь и содержимое не выводятся.

## V9. Выбор двух вакансий

Откройте вакансию и выберите вторую в разделе «Сравнение вакансий». Рядом
показаны места, диапазоны L–H, доля известных данных и различающиеся условия
с цитатами. Разбор места и список допущений берутся из E7. Если в отчёте
нет нужной пары, сервер отдаёт проекцию из того же ресурса отчёта для
опубликованной ревизии. Внешних вызовов при сравнении нет.

Допущение появляется только для сохранённого расчёта по одной строке, который
может изменить порядок пары. «Сбросить» очищает вид. Рейтинг, решение HR и
печатный пакет сохраняют исходные значения. Для импортированного старого
отчёта доступны сохранённые сравнения. Если данных не хватает, вид сообщает
об этом.

## V10. Проверки

Прогон на macOS 15.7.3 arm64, Python 3.13.17, Node 24.14.0, Chrome 157.0.8103.52.
Прошли 412 тестов прототипа с публичными весами NER, 42 JS-теста, 10 тестов
репозитория и оба CLI replay. В сквозном проходе внешний трафик и ошибки
JavaScript отсутствовали.

```sh
.venv/bin/python scripts/check_repository.py
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python -m unittest discover -s prototype/tests -q
node --test prototype/tests/test_web_*.cjs
.venv/bin/python scripts/check_cli_replays.py
```

HTTP-тесты проверяют loopback, Host, Origin, токен сессии, предел 25 МБ до
чтения тела, traversal, неизвестный run-id, повторы запуска и нераспознанные
вакансии в сравнении. Данные тестов синтетические.

Сквозной браузерный проход. Повреждённый PDF получил диагностику, после
замены набора прочитаны DOCX и три PDF. Mock SDK сформировал отчёт 3/3.
Проверены открытие по адресу, две вакансии ниже первого места, what-if и
сброс, два фрагмента, клавиатура, печать A4 и недоступный запуск. Записанный
пакет проверяется на исходном рейтинге. При режиме печати what-if скрывается.

В отдельном браузерном прогоне с управляемыми ответами проверены потеря ответа
на запуск и повтор с тем же ключом, восстановление обновлений после сетевого
сбоя, отмена, устаревшее решение, удаление и переключение A → B → A. Вымышленные
HTML-строки в имени и цитате отображаются текстом. Эти проверки моделируют
состояния сервера и не обращаются к внешней модели.

Видео приёмки с SHA и печатный пример передаются отдельно от исходников.
