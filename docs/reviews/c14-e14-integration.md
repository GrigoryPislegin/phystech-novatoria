# C14 / E14 — интеграция 14 ноября

Приняты коммиты Егора до `49d92fa`: evidence-0.2, доли подтверждённого/спорного/неизвестного, данные осей и проверки сохранности профессионального текста. Последнее исправление отправляет опыт третьих лиц и простое намерение работать на сверку, а не засчитывает их кандидату. Формула v3 не изменена.

## Что подключено

- `RequirementsAnalysis` получает необязательные `factors` вместе с требованиями; базовый сценарий по-прежнему содержит семь запросов для трёх вакансий. Категории не меняют веса или итоговый score.
- `job.requirement_factors` сохраняет предложение модели; `job.competency_axes` сервер пересчитывает из unit/weights/evidence. Старые отчёты без новых полей остаются читаемыми. Нормализованные дубли с несогласованными или неполными категориями целиком остаются вне диаграммы.
- Privacy 0.7 сохраняет распознанные технические термины только внутри ограниченных профессиональных конструкций. Заголовки клиентов и контекст работодателя запрещают такое исключение. Имена, структурные поля и известные скрытые значения по-прежнему имеют приоритет.
- Адресное поле скрывается вместе с меткой, включая продолжение улицы/дома через перенос строки или `;`. Это предотвращает повторное принятие следующей профессиональной строки за адрес. Регистрация патента не считается адресом.
- Если значение категории совпало со скрытым значением, необязательная группировка может быть удалена локально. ID сначала валидируются, весь оставшийся DTO проверяется повторно. Исключения из проверки скрытых значений не вводятся.
- Новые E14-регрессии включены в allowlist Docker и проверку сборки.

## Проверки и границы

Независимое ревью выявило пять конкретных проблем. После исправлений проверяющий подтвердил 76 целевых тестов и девять прямых проверок real NER → redaction → source finalization → outbound boundary. Отдельно прошёл набор из 70 регрессий, 41 UI-тест и policy_compare без новых регрессий.

Полный объединённый Python-набор после последнего коммита Егора: **559 PASS** с локальным NER и loopback HTTP, 19,557 с. Эти результаты не являются измерением качества модели.

Известное ограничение: совпадение скрытого значения с уже существующим ключом схемы, например `profile.stack`, остаётся fail-closed. Новый тест `Stack` относится к запросу требований; полный pipeline проверен на категории `Education`. Это не заявление об устранении всех коллизий схемы.

CLI Markdown/CSV уже восстанавливают локальные оригиналы. В браузере подключение display-data и краткой сводки остаётся задачей V13; это изменение не объявляет UI готовым. Проверка 30 вакансий с живой моделью и облачное развёртывание также пока не подтверждены.
