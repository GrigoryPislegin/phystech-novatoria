# C14 / E14 — интеграция 14 ноября

Приняты коммиты Егора до `49d92fa`: evidence-0.2, доли подтверждённого/спорного/неизвестного, данные осей и проверки сохранности профессионального текста. Последнее исправление отправляет опыт третьих лиц и простое намерение работать на сверку, а не засчитывает их кандидату. Формула v3 не изменена.

## Что подключено

- `RequirementsAnalysis` получает необязательные `factors` вместе с требованиями; базовый сценарий по-прежнему содержит семь запросов для трёх вакансий. Категории не меняют веса или итоговый score.
- `job.requirement_factors` сохраняет предложение модели; `job.competency_axes` сервер пересчитывает из unit/weights/evidence. Старые отчёты без новых полей остаются читаемыми. Нормализованные дубли с несогласованными или неполными категориями целиком остаются вне диаграммы.
- Privacy 0.7 сохраняет распознанные технические термины только внутри ограниченных профессиональных конструкций. Заголовки клиентов и контекст работодателя запрещают такое исключение. Имена, структурные поля и известные скрытые значения по-прежнему имеют приоритет.
- Адресное поле скрывается вместе с меткой, включая продолжение улицы/дома через перенос строки или `;`. Это предотвращает повторное принятие следующей профессиональной строки за адрес. Регистрация патента не считается адресом.
- Если значение категории совпало со скрытым значением, необязательная группировка может быть удалена локально. ID сначала валидируются, весь оставшийся DTO проверяется повторно. Исключения из проверки скрытых значений не вводятся.
- Новые E14-регрессии включены в allowlist Docker и проверку сборки.

CLI Markdown/CSV уже восстанавливают локальные оригиналы. В браузере подключение display-data и краткой сводки остаётся задачей V13; это изменение не объявляет UI готовым. Проверка 30 вакансий с живой моделью и облачное развёртывание также пока не подтверждены.

## Исправление неподтверждённой обязательности

После полной проверки приватности ответа модельный адаптер может отбросить только неверный optional mandatory_quote. ID, text и основные quote не меняются; весь оставшийся DTO обязан пройти прежний core/source контракт и повторную privacy-проверку. Неточная основная цитата, дубли ID, приватное значение или неизвестная PRIV-метка всё ещё отклоняются. Дополнительного запроса для такого удаления нет.

Нормализация не назначает обязательность: per-job `contract_warnings` содержит `{code: mandatory_status_unconfirmed, requirement_id}`. Эти записи становятся пунктами `mandatory_unbound` в очереди. Подтверждение списка их не закрывает; требуется явное ознакомление. Непустые предупреждения входят в хеш отчёта, поэтому их изменение делает прежние решения устаревшими; отсутствие/пустой список сохраняет хеш старых отчётов.

На сохранённых прошедших privacy ответах шестой попытки новая локальная проверка удерживает 15/15 и 8/8 требований, в обоих случаях четыре пометки отправляются на сверку; сетевых вызовов нет. Полный набор после исправления: **563 Python PASS**, 19,434 с. Ревью подтвердило 112 целевых проверок и путь решений через RunStore, затем отдельные 45 проверок исправления хеша. Следующая одноразовая live-проверка ограничена $0.20; с учётом полного резерва прерванной попытки общий верхний резерв $0.559729 < $1. Модель остаётся Luna.

Docker `recruiter-prototype:c14-cec5114-arm64` собран: 167 встроенных тестов, оба privacy smoke PASS без внешнего API. Это образ до последнего исправления обязательности. На сервер переданы только 59 разрешённых файлов кода/тестов и публичные NER-веса (контекст SHA256 `6643120251c4aaaf965b16b1dc95994e13f5ccf485deb1afec701c93ef4551c5`); запущена native amd64 сборка. Серверные приложения и публичный Funnel443 пока не менялись.

## Privacy 0.8: короткие профессиональные цитаты

Седьмая попытка завершилась **0/3**: ответ facts отклонён по двум PERSON-находкам. Отклонённый текст не сохранён; точные виновные фрагменты неизвестны. Оценочная стоимость $0.0039103, резерв $0.0105448. Успешной live-приёмки пока нет.

Отдельно воспроизведён дефект коротких профессиональных цитат: `Pixel Perfect`, `Service Desk`, `Adaptive Design`, `Code Review` после разделения JSON-полей принимаются структурным детектором за английское имя. В 0.8 исключение наследуется только из распознанного профессионального фрагмента успешно защищённого исходника. Поля работодателя/имени не дают такого происхождения, а известное скрытое значение всегда блокируется. Табличная строка навыков принимается лишь целиком как список технических терминов. Голые домены, включая кириллический `.рф`, скрываются отдельным правилом; `.js` не считается доменом этим правилом. Контекстные ошибки NER остаются возможны.

Независимая повторная проверка закрыла три обхода в строках таблицы и пропуск кириллического домена. Полный набор: **567 Python PASS**, 19,816 с, без внешнего API. Новая одноразовая попытка №8 разрешена прежним согласованием: тот же CV №2 и три вакансии, Luna, предел $0.20; суммарный консервативный резерв с ней $0.5702738 < $1. Добавлена локальная диагностика вида детектора и происхождения находки без сохранения отклонённых текстов.

Подцитаты профиля и условий привязаны к указанному fact_id; весь изменённый DTO повторно проходит privacy и прежние контракты. Без нового API сохранённый ответ №8 проходит source validation с 82/82 точными фактами, восстановлено 8 цитат с учётом профиля; профиль остаётся needs_review.

Следующая одноразовая попытка №9 — прежний набор, Luna, максимум $0.20, суммарный верхний резерв $0.5913903 < $1. Ещё не подтверждена live-приёмка.
