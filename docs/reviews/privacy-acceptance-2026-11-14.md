# N-C3: измерение локального маскирования на синтетике

14 ноября 2026. Собственный `local-privacy-0.2`, закреплённые публичные Slovnet/Navec, без OpenAI, `.env` и реальных резюме. Это регрессионный корпус команды, не оценка анонимности или recall на реальных CV.

## Воспроизведение

```sh
.venv/bin/python -m evaluation.privacy_acceptance --out data/private/privacy-check-new
```

Каталог должен быть новым. При наличии моделей команда создаёт `privacy.json` и `privacy.md`, даже если обнаружены ошибки. Exit 0 — все размеченные фрагменты обработаны согласно ожиданиям; 1 — есть пропуск/лишнее маскирование; 2 — неполное выполнение, недоступны модели или неверен ввод/вывод. В текущем корпусе ожидается **exit 1**, поскольку известные потери профессионального текста не исключаются из метрик. При недоступных моделях 0/21 случаев оценено, значения метрик `null`, а не 100%.

Данные: [21 полностью вымышленный случай](../../evaluation/fixtures/privacy/cases.json), [фактический JSON](../../evaluation/results/privacy-2026-11-14-v02/privacy.json), [таблицы по каждому фрагменту](../../evaluation/results/privacy-2026-11-14-v02/privacy.md). JSON фиксирует SHA256 корпуса, моделей и нормализованных источников. Аннотации заданы независимо от вывода детектора: ожидаемый текст, роль, начало/конец в NFKC-тексте без Unicode Cf. Это полуинтервалы Python-символов, не байты и не позиции исходного ненормализованного документа.

## Фактический результат

| Измерение | Результат |
|---|---:|
| Полностью выполненные случаи | 21/21 |
| Полностью замаскированные размеченные идентификаторы | 19/19 |
| Сохранённые размеченные профессиональные фрагменты | 24/28 |
| Неизмеренные фрагменты | 0 |
| Внешние модельные вызовы | 0 |

Идентификатор засчитывается только при закрытии всего размеченного диапазона. Одного совпавшего символа недостаточно; пересекающиеся находки не считаются дважды. Профессиональный фрагмент считается потерянным при маскировании любой его части. Неизвестные/неразмеченные части текста не входят в эту долю. Поэтому 19/19 не означает, что система находит любые персональные данные.

Оставшиеся потери: Rust в резюме «Пишу код на Go и Rust.» (в вакансии с другим контекстом сохраняется); заголовок Senior Python Developer, ошибочно похожий на английское имя; две полные даты профессионального опыта. Это четыре фрагмента в трёх случаях. Присутствуют отрицательные контроли: SQL в контексте подрядчика и Excel в контексте работодателя должны скрываться; широкого исключения технологий нет. ORG-маскирование даёт текущий runtime-флаг о возможной потере профессиональных сведений; для других классов сохраняется общая необходимость локальной проверки, отдельного точного детектора потери профессионального смысла пока нет.

Первый прогон на 18 случаях с предыдущим правилом дал 15/16 идентификаторов и 21/25 профессиональных фрагментов. Найден явный пропуск «My name is John Smith». Добавлено узкое структурное правило для явного представления; оно сохраняет последующее профессиональное предложение. Независимое ревью обнаружило частичное имя с инициалом и вариант с `and`: они внесены в корпус и исправлены. Не заявляем поддержку всех английских имён/языков/свободных формулировок. Корпус после ревью расширен, поэтому общие доли двух прогонов нельзя считать сравнением на одинаковой выборке.

## Проверки самого измерителя

`prototype/tests/test_privacy_acceptance.py`: частичный идентификатор, пересекающиеся находки, потерянный навык, пустой корпус, блокировка по остаточному обнаружению, отсутствие моделей, нормализованные позиции, известные ограничения в знаменателе и сохранение фразы после представления. Сначала регрессии на пропуск/инициалы/пустой корпус падали; после исправлений 10 tests PASS. Наличие синтетической разметки и этих тестов не заменяет независимую оценку реальных документов.
