## E3 — `prototype/evidence.py`

### Что решает

Точная цитата сейчас доказывает только то, что фрагмент есть в тексте. Модуль привязывает каждое доказательство к позиции, предложению и заголовку списка в **обработанном** тексте и выдаёт структурную проверку. Смысл он **не** подтверждает: вывод модели остаётся неподтверждённым, пока его не проверит человек.

### Состояния проверки строки (`RowCheck.state`)

| state | Когда | Это не… |
|---|---|---|
| `structure_ok` | Все цитаты найдены, однозначны, совпадают с целым предложением, связаны с требованием и не стоят под заголовком списка | …не «подтверждённое соответствие»: `meaning` всегда `model_claim_unverified` |
| `needs_review` | Структура спорная (причины ниже) | …не пятый статус соответствия: статус модели (`full/partial/fail/unknown`) сохраняется |
| `no_evidence` | Статус `unknown`, доказательств нет — нехватка сведений | …не ошибка |
| `invalid` | Выдуманный id факта, цитата не найдена, неверный диапазон или источник, unknown с доказательством | …не `unknown`: техническая ошибка остаётся ошибкой |

Состояние обязательности (`MandatoryCheck.state`): `structure_ok`, `needs_review`, `not_mandatory`, `invalid`.

### Коды причин

| Код | Тяжесть | Смысл |
|---|---|---|
| `quote_is_fragment` | review | Цитата короче своего предложения; в `context` — предложение целиком |
| `quote_spans_sentences` | review | Цитата захватывает несколько предложений |
| `evidence_not_linked` | review | Нет ни одного общего термина требования и доказательства |
| `heading_context` | review | Цитата — пункт списка под заголовком (например «Не работал с:»); в `context` — «заголовок → пункт» |
| `ambiguous_location` | review | Цитата факта стоит в разных местах резюме, позиции нет |
| `mandatory_not_linked` | review | Обязательность сказана в другом предложении или блоке |
| `mandatory_spans_segments` | review | Цитата обязательности захватывает несколько строк или предложений |
| `ambiguous_requirement_location` | review | Цитата требования повторяется в вакансии, и обязательность относится не ко всем вхождениям |
| `unknown_fact_id`, `quote_not_found`, `range_mismatch`, `empty_quote`, `unknown_source`, `source_mismatch`, `missing_evidence`, `unknown_with_evidence`, `duplicate_fact_id`, `requirement_mismatch`, `unknown_requirement_id` | invalid | Технические и структурные ошибки |

### Функции

```python
Source.of(source_id: str, text: str) -> Source            # text — обработанный текст; хранит sha256
locate(source: Source, quote: str, start: int | None = None) -> Located
verify_span(span: Span, sources: dict[str, Source]) -> list[Reason]   # повторная проверка сохранённого доказательства
check_row(row: Row, requirement: Requirement, facts: Facts, cv: Source) -> RowCheck
check_mandatory(requirement: Requirement, vacancy: Source) -> MandatoryCheck
check_pair(requirements, facts, evaluation, cv: Source, vacancy: Source) -> PairCheck
```

Все результаты — Pydantic-модели. `model_dump()` можно положить в `report.json` как есть. `Span` хранит `source_id`, `source_sha256`, `start`, `end`, `quote`, `sentence` и `heading`.

### Пример (синтетика C01)

Вход: CV `Не работал с Python, планирую изучить.`, факт `quote='Python'`, строка `full`.

```json
{"requirement_id": "r1", "status": "full", "state": "needs_review",
 "meaning": "model_claim_unverified",
 "reasons": [{"code": "quote_is_fragment", "severity": "review", "fact_id": "f1",
              "context": "Не работал с Python, планирую изучить"}]}
```

Рекрутер видит предложение целиком, в том числе «Не работал с». (В `context` и `sentence` концевая пунктуация отрезана.) Список отрицаний не используется: срабатывает структурное правило «цитата короче своего предложения».

### Правила (структурные, не смысловые)

1. **Привязка.**
   - Цитата ищется в обработанном тексте.
   - Если передана позиция, `text[start:start+len(quote)]` должен совпасть дословно.
   - Если цитата встречается несколько раз в разных предложениях, а позиции нет, место молча не выбирается.
2. **Целое предложение.**
   - Доказательство `full/partial/fail` должно совпадать со своим предложением, без маркера списка и концевой пунктуации.
   - Предложение заканчивается на `.!?;` только перед пробелом или концом строки, поэтому «Node.js», «ASP.NET Core», «3.5 года» не режутся.
3. **Связь с требованием.** Нет ни одного общего содержательного термина → `evidence_not_linked`. Общий термин связь **не доказывает**: например, «Строил отчёты в Excel» и «Python для автоматизации отчётов» делят слово «отчёт». Отсутствие общего термина только отправляет строку на проверку.
4. **Заголовок списка.**
   - Пункт под строкой, которая кончается на «:», получает `heading_context`, а заголовок виден в `Span.heading`.
   - Код не читает смысл заголовка, поэтому на проверку уходят и нейтральные «Навыки:».
   - **Решение для Григория:** это осторожный выбор. На резюме в виде списков строк на проверку станет больше. Альтернатива: показывать заголовок, но не повышать состояние. Тогда «Не работал с:\n- Python» пройдёт как `structure_ok`.
5. **Обязательность.** `mandatory_quote` связан с требованием, только если выполнено одно из двух условий:
   - он стоит в том же предложении, что и цитата требования;
   - он является строкой-заголовком («Обязательно:»), а требование стоит в **непрерывном списке** прямо под ним (`-`, `*`, `•`, `–`, `1.`, `2)`). Список заканчивается на пустой строке и на первой строке, которая не является пунктом («Желательно: SQL», «Будет плюсом»).

### Остаточные ошибки (честно)

- **Целое предложение с неверным выводом.** Если модель процитирует всё предложение «Не работал с Python, планирую изучить.» и поставит `full`, структура пройдёт: смысловую ошибку код не видит. Поэтому `meaning` всегда `model_claim_unverified`.
- **Случайный общий термин.** Он даёт `structure_ok` и для `fail` (см. правило 3). **`structure_ok` — не основание для `violated`** (см. п. 4 подключения).
- **Обязательность через запятую.** В «Python обязателен, SQL желателен.» обязательность Python формально стоит «в том же предложении», что и SQL. Такая разметка пройдёт.
- **Сокращения с пробелом** («т. е.», «2019 г. — н. в.») режут предложение. Строка тогда уйдёт на проверку, а не пройдёт молча.
- **Ненумерованный перечень под заголовком** (строки без маркеров) не считается блоком обязательности и уходит на проверку. Это ошибка в безопасную сторону.

## E4 — `prototype/requirements_review.py`

### Что решает

Если из «Python обязателен. Go обязателен.» модель извлекла один Python, сейчас получится `complete=true` и L=100. Модуль разделяет два состояния: «все вакансии обработаны» и «извлечённый список требований проверен рекрутером». По умолчанию список **не подтверждён**.

### Функции

```python
source_sha256(text: str) -> str
requirements_sha256(requirements: Requirements) -> str        # каноничный JSON: id, text, quote, mandatory_quote; порядок не важен
draft(vacancy_id: str, text: str, requirements: Requirements) -> RequirementsDraft
    # .state == 'unconfirmed'; .uncovered — предложения вакансии, не задетые ни одной цитатой (подсказка для сверки)
approve(vacancy_id, text, requirements, approved_at: str) -> RequirementsApproval
    # вызывать только по явному действию рекрутера в CLI; модель такую структуру не создаёт
check(approval: RequirementsApproval | dict | None, vacancy_id, text, requirements) -> ApprovalCheck
    # state: 'confirmed' | 'unconfirmed' | 'stale' | 'invalid'; reasons с кодами
summarize(processing_complete: bool, checks: dict[str, ApprovalCheck], *, expected_ids: list[str]) -> RunReviewSummary
    # вакансия без проверки = unconfirmed; проверка чужой вакансии = invalid;
    # processing_complete и requirements_confirmed независимы; final_allowed = оба True
```

### Пример (синтетика C04)

```python
d = draft('job-001', 'Python обязателен. Go обязателен.', only_python)
d.state      # 'unconfirmed'
d.uncovered  # ['Go обязателен'] — видно, что Go не попал в список
```

Коды `stale`: `source_changed`, `requirement_added`, `requirement_removed`, `requirement_changed`, `mandatory_changed`.

Коды `invalid`:
- `malformed` — это не подтверждение рекрутера: JSON модели или `approved_by` не `recruiter`;
- `schema_version`;
- `foreign_vacancy`;
- `hash_mismatch` — подтверждение не соответствует своему же списку;
- `duplicate_ids`.

Это однопользовательский CLI: подтверждение не является аутентификацией или подписью, а только привязкой решения рекрутера к конкретному тексту и списку. `uncovered` работает на уровне предложений: в «Обязательно знание Python и Go.» при одном извлечённом Python предложение уже задето, и Go в подсказку не попадёт. Подсказка не доказывает отсутствие пропусков.

## Что подключить Codex

1. **pipeline.py**, после `validate_pair` (стр. 35): вызвать `evidence.check_pair(requirements, facts, evaluation, Source.of('cv', safe_resume), Source.of(jid, text))` и положить `model_dump()` в результат вакансии под ключом `evidence_checks`.
2. **pipeline.py**, после извлечения требований:
   - положить `requirements_review.draft(jid, text, requirements)` в результат под ключом `requirements_review`;
   - подтверждение рекрутера читать из закрытого каталога CLI (файл на вакансию) и проверять через `check(...)`;
   - сводку строить через `summarize(ranking['complete'], checks, expected_ids=[все jid запуска])`.
3. **write_report**:
   - у строки с `needs_review` показывать причину и `context`;
   - у `structure_ok` писать «структура проверена, смысл — утверждение модели»;
   - в шапке отчёта: «Требования подтверждены рекрутером: N из M» и список `uncovered` для неподтверждённых вакансий.
4. **scoring.rank** (решение Григория, формулу L/H не меняет):
   - не выдавать `review_none_fit`, пока каждая обязательная строка `fail` во **всех** вакансиях не просмотрена человеком: `structure_ok` для этого недостаточно;
   - не выдавать `review_top` как итог, если у вакансий первого места есть `needs_review` по обязательным требованиям или `summarize(...).final_allowed` ложно.
5. **SYSTEM в model.py**: «quote факта — целое предложение резюме, без сокращения; для обязательности — фраза в том же предложении или заголовок списка, к которому относится требование».
