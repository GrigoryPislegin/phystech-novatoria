# V6. Проверка сохранённых отчётов

Раннер читает сохранённые JSON и ожидания E6, которые Егор опубликовал в
[PR №16](https://github.com/GrigoryPislegin/hackathon-phystech-nanimai/pull/16)
на коммите `5da6e81`. В наборе 16 вымышленных случаев по фронтенду, учёту
основных средств и организации учебного процесса. Разметка имеет статус
`draft`. Шесть случаев выделены в holdout. Когда рядом с ожиданиями есть
`holdout.sha256`, раннер сверяет список этих случаев и их контрольную сумму.

В `evaluation/fixtures/documents/` лежат шесть вымышленных резюме и три вакансии
из того же набора. PDF содержат текстовый слой. Тест извлекает текст всех девяти
документов через обычный парсер прототипа и сверяет его SHA-256 с манифестом.

## Воспроизведение

Из корня проекта с установленными зависимостями. Ожидания из PR №16 доступны
в `evaluation/expectations/egor/e6-cases.json`. Для другой сохранённой версии
используйте `--expectations`.

```sh
v6_dir=$(mktemp -d)
python -m unittest discover -s evaluation/tests -v
python -m evaluation.example_reports --out "$v6_dir/replay"
python -m evaluation.saved_reports --reports "$v6_dir/replay" --out "$v6_dir/summary"
```

`example_reports` прогоняет обычный pipeline с заранее подготовленными
ответами. В двух случаях с ожидаемо пропущенной вакансией он возвращает
ошибку модели в pipeline, чтобы в сохранённый отчёт попали и ошибка, и пропуск.
Эти отчёты проверяют раннер и связку отчёта с ожиданиями. Качество модели ими
не измеряется.

Для отрицательной проверки создайте отчёты в отдельной папке. В случае
`E6-FE-01` статус по React останется допустимым, но строка получит реальную
цитату про другой навык. В сводке должен появиться `wrong_evidence`.

```sh
python -m evaluation.example_reports --out "$v6_dir/wrong" --wrong-evidence
python -m evaluation.saved_reports --reports "$v6_dir/wrong" --out "$v6_dir/wrong-summary"
# Ожидаемый код завершения второй команды: 1.
```

## Проверка на macOS 15.7.3 arm64, Python 3.13.17

- 14 тестов раннера прошли. Из всех девяти DOCX/PDF извлечён текст с ожидаемым хешем.
- Эталонный replay прошёл 16 из 16 случаев, 66 из 66 строк, 16 рекомендаций,
  6 отношений мест, 4 проверки условий и 9 проверок эквивалентности.
- Ошибочная цитата `E6-FE-01/fe-react` дала `wrong_evidence` и код 1. Пустой
  каталог в режиме `live` дал 16 `not_run` и `model_quality: not_measured`.

## Формат и границы проверки

- Передайте папку с файлами `<case_id>.json`, например `E6-FE-01.json`.
  Раннер читает сохранённый `report.json` формата 0.1. Поддерживаются id
  вакансий из E6 и id, которые штатный CLI вычисляет из исходного текста.
  Цитаты и хеши сверяются с обработанными текстами из ожиданий. Если защита
  изменила текст в запуске, для такого отчёта нужны соответствующие
  обработанные тексты и ожидания, привязанные к ним.
- Раннер сопоставляет требования один к одному по буквальному пересечению
  цитат в источнике, сверяет обязательность, допустимые статусы, факты и
  цитаты. Пропуск строки и ошибка обработки учитываются отдельно от
  `unknown`. Он проверяет рекомендацию, отношения мест, равнозначные
  формулировки и условия при наличии E5. Без E5 условия имеют `not_run`.
  Сохранённые утверждения профиля сверяются с цитатами и фактами из резюме.
- В `summary.json` и `summary.md` есть знаменатели, ошибки и пропуски
  отдельно по областям, dev и holdout. Код 0 означает отсутствие обнаруженных
  ошибок среди представленных отчётов. Код 1 означает провал проверки, 2 —
  ошибку запуска раннера. Пустая папка отчётов даёт все случаи `not_run`.
- По умолчанию принимается `--mode replay`. `--mode live` только читает
  уже сохранённые отчёты, помеченные движком как live. Раннер не вызывает API,
  не подтверждает происхождение файла и не оценивает свободный текст модели.
  Формулировки из `forbidden_conclusions` вынесены в `manual_review`.
