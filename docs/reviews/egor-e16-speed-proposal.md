# E16 — ускорение 1 CV → 30 вакансий: критический путь и план

14 ноября 2026, Егор / Fable. Задача #49. База `main` (`8b13b77`). Это предложение и расчётная модель; файлы model, privacy, pipeline и application не менялись. Реальных вызовов не было: числа ниже — модель расписания на сообщённых замерах, не измерение.

## Критический путь сейчас

Защита ~5 с → facts ~50 с → 30 вакансий через 3 воркера, в каждом последовательно requirements → evaluation (по 15–50 с). Это 55 + 10 × 65 ≈ 700 с; модель даёт медиану 726 с при фактических 680 с.

Время определяют: facts блокирует всё, хотя requirements от фактов не зависят; 60 вызовов идут в 3 слота; длительность вызова ≈ число генерируемых токенов.

## Варианты

`python -m evaluation.schedule_model` — медиана / p90, секунды.

| Вариант | 3 | 6 | 10 | 16 слотов | без очереди |
|---|---|---|---|---|---|
| Порядок прежний | 726 / 769 | 411 / 434 | 283 / 300 | 212 / 223 | 146 |
| B: facts ∥ все requirements, общий пул | 683 / 720 | 356 / 376 | 225 / 239 | 153 / 162 | 103 |
| B + вывод −40% (`--scale 0.6 --facts-scale 0.6`) | | | 137 | 94 | 64 |

Число запросов во всех вариантах 61; токены меняются только в последней строке.

- 1–2 минуты достижимы при B, 10–16 слотах и сокращении вывода.
- ≤60 с на текущих латентностях недостижимо без сокращения самого facts: цепочка facts → evaluation остаётся.
- Объединять requirements и evaluation в один вызов не стоит: выходные токены складываются, выигрыш — только накладной вход; теряется проверка требований по источнику до оценки, вызов нельзя начать до facts, отказ стоит всей вакансии.

## Минимальный патч (зона Codex)

1. **pipeline.py.** Один пул на W слотов: после защиты сразу стартуют facts и requirements всех вакансий; evaluation вакансии — когда готовы её requirements и facts. Проверки и правило остановки прежние. Предел `max_concurrency <= 6` поднять и вынести в параметр.
2. **model.py.** Ограниченный повтор только для 429/5xx (сейчас `max_retries=0`: при 10+ слотах первый 429 — потерянная вакансия). Резерв бюджета на вызов ≈ $0,007; 16 одновременных ≈ $0,11 при лимите $1.
3. **Меньше вывода без потери требований и цитат.** evaluation: не генерировать `question` (уже строится локально), `comment` — одна короткая фраза. facts: не генерировать `text` факта (в evaluation он не отправляется), локально `text = quote`.
4. **Проверить reasoning-токены** в `usage.output_tokens_details`; если заметны — понизить усилие для requirements и facts с проверкой качества.
5. **Общий префикс** (низкий приоритет): факты первыми и со стабильным кодированием меток — экономит вход, на генерацию не влияет.

## Что замерить до объявления результата

Один прогон 1 CV + 30 при B и 10 слотах: общее время, p50/p95 по стадиям, число 429, usage по стадиям, 30 из 30. Затем сравнить с текущим отчётом число требований, долю unknown и исключённых маркеров; регрессии E13–E15 должны остаться зелёными.
