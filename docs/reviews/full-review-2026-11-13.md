## Находки по приоритету

### R1 · P1 · JSON-экранирование ломает настоящие ссылки Certum

`prototype/model.py:55–58,71`, `prototype/privacy.py:9,26–31`. Источник `Навыки:\nчеловек#1: Python` с настоящим переносом строки проходит check как выданная ссылка. После json.dumps regex распознаёт `nчеловек#1`, которого нет в issued_refs. Запрос блокируется до SDK; аналогично TAB и многострочные цитаты в ответе. Воспроизведено, SDK-вызовов 0.

Исправление: проверять декодированные динамические строковые значения перед сериализацией/после разбора, сохранив проверку всех полей и запрещённых ссылок. Не лечить расширением списка разрешённых refs или отключением scan. Владелец **C1**, до защищённого live. Регрессии: LF/TAB/кавычки/обратные слеши/списки/вложенные структуры; настоящее проходит, поддельное блокируется до SDK.

### R2 · P1 · SDK debug выводит тело запроса

`prototype/model.py:47–65`. При наследованном `OPENAI_LOG=debug` SDK пишет json_data с обработанными текстами CV/вакансий/фактов. Маскирование текста исключения в CLI этот канал не закрывает. Независимый ревьюер воспроизвёл на закреплённом SDK и httpx.MockTransport: вымышленная контрольная строка появилась в stderr, сетевых запросов не было. Ручной ночной live запускался с отключённым logging; находка касается штатного CLI.

Исправление: принудительная безопасная политика журналов в продуктовой точке входа и адаптере; не печатать payload, ответы, ключи и DSN. Сохранить безопасные коды стадий. Владелец **C1**. Регрессия в отдельном процессе с OPENAI_LOG=debug и тестовыми значениями: ни stdout, ни stderr не содержат контрольных строк.

### R3 · P1 · Обработано 3/3 не означает, что извлечены все требования

`prototype/pipeline.py:42–50`, `prototype/contracts.py:78–82`. Вакансия содержит обязательные Python и Go, ответ requirements оставляет только Python. Оценка full по Python принимается: complete=true, review_top, L=100. Проверка coverage охватывает только извлечённый список, а не исходную вакансию. Воспроизведено.

Это ограничение доверия к извлечению, а не арифметическая ошибка. Разделить полноту обработки вакансий, подтверждение состава требований и качество извлечения; показать статус неподтверждённого списка, предусмотреть проверку рекрутером. Нужен маленький эталон с пропусками. Владельцы **E1 → C2**. Нельзя обещать автоматическое доказательство полноты по regex или одной второй модели.

### R4 · P1 · Смысл цитаты и обязательность всё ещё не доказаны

Исходный простой случай чужой цитаты исправлен, общий случай — нет.

Владельцы **E1 → C2**: контекст цитаты, связь факта с требованием, ручное подтверждение обязательности и раздельная оценка ошибок. Минимальная длина цитаты не является решением семантики. Не менять веса/формулу без решения эксперта. До проверки — только гипотеза для рекрутера, никакого автоматического отказа.

## Что не является новой ошибкой

- unknown и fail дают одинаковый вклад в L, но различаются H/coverage/воротами. Порядок подробной/короткой вакансии — вопрос принятой политики, не тихая правка формулы. Решение **E2**, реализация **C2** после ответа.
- Нет UI/ATS/OCR/HH/многопользовательского API — согласованный объём первого CLI, не повод добавлять перед консультацией.
- Проверка точных цитат, ссылок на факты, неполного запуска, ничьих, бюджета и закрытого экспорта присутствует и покрыта тестами. Это не гарантирует смысловой точности.
