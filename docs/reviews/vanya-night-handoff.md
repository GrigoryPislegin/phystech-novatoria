# V11. Проверка сохранённого запуска

[Задача №10](https://github.com/GrigoryPislegin/hackathon-phystech-nanimai/issues/10) продолжает [поставку V8–V10](vanya-v8-v10.md). Интерфейс читает историю и записывает решения через существующий локальный сервис. Просмотр, решения и экспорт работают с опубликованной ревизией и не запускают анализ.

## Как пройти сценарий

1. Откройте «Запуски» и выберите сохранённый результат. Вверху видны режим, число обработанных вакансий, политика, ревизия и состояние подтверждения.
2. Выберите вакансию. В разделе «Проверка рекрутером» разверните замечание E8. В нём видны приоритет, причина, действие и доступные фрагменты обоих документов. Из замечания можно перейти к оценке конкретного требования или к условию.
3. Откройте «Состав требований», проверьте формулировки, обязательность, цитаты вакансии и фрагменты вне списка. Кнопка в конце блока подтверждает показанную ревизию. Отметка об ознакомлении оставляет оценку требования прежней.
4. После перезагрузки ссылка с `?run=…` снова открывает сохранённый запуск. «Отчёт для менеджера» выгружает выбранную вакансию, ревизию и состояние проверки в HTML для печати. Конфликт условий, принятые исключения, неполнота и предупреждение о маскировании сохраняются, если они есть.
5. «Удалить» открывает диалог с меткой выбранного запуска. Удаляются обработанные копии, отчёт и решения этой записи в локальном хранилище. Скрипт приёмки удаляет только свою синтетическую запись.

Импортированный JSON открывается с пометкой о внешнем непроверенном источнике. Подтверждения и отметки передачи доступны через сохранённый локальный запуск. При конфликте версий сервер возвращает актуальный отчёт, после чего рекрутер сверяет его и заново выбирает действие.

## Приёмка

macOS 15.7.3 arm64, Python 3.13.17, Node 24.14.0, Chrome 157.0.8103.52, Playwright 1.62.1. Браузерные проходы выполнены на 1280×720, проверка длинного текста также на 640×480. Спорный печатный пакет проверен в A4.

Код в записи и браузерной приёмке — `686487d87ebfcb51528d705b30928e42b715894d`. Запись длится 1:48. Локально прошли 412 Python-тестов прототипа, 44 JS-теста, 10 тестов репозитория и оба CLI replay. Этот SHA также прошёл [Repository checks](https://github.com/GrigoryPislegin/hackathon-phystech-nanimai/actions/runs/43575463238) и [Docker acceptance](https://github.com/GrigoryPislegin/hackathon-phystech-nanimai/actions/runs/43575532724).

| Сценарий | Что должно произойти |
| --- | --- |
| Успешный | Escape отменяет подтверждение. Подтверждение состава создаёт ревизию 2. Отметка передачи создаёт ревизию 3. Она видна после A → B → A и перезагрузки, в HTML указан тот же результат. |
| Спорный | У одинакового «Python» видны два разных заголовка. «В офисе» и «только удалённо» видны рядом. Принятое исключение видно в интерфейсе и печати. Неоднозначная цитата продолжает блокировать передачу, предупреждение о маскировании сохраняется. |
| Неполный и прерванный | Неполный рейтинг показывает пропущенную вакансию и печатается как предварительный. Прерванная после рестарта запись без отчёта не открывается как готовая. |
| Конфликт, отказ, повтор | Проверено в браузере с подставными ответами. После 409 выполняется чтение, требуется новое действие пользователя. Если чтение тоже не удалось, устаревшая ревизия остаётся с предупреждением и без действий. Отказ сервера выводит безопасное сообщение. Два Enter подряд дают один запрос записи. |
| Обратный путь и импорт | Проверено в браузере и на локальном сервере. Удаление выбранной записи сохраняет соседнюю. Неизвестная ссылка и повреждённый JSON объясняют отказ. Загрузив внешний JSON с заявленной отметкой HR, пользователь получает просмотр и печать без серверных полномочий. |
| Границы | Проверены текстовые метки разметки в имени, цитате и комментарии, запреты traversal и удаления symlink, отказ для активного запуска, loopback, Host, Origin, токен и лимит HTTP 25 МБ. Отдельно браузер повторяет создание после потерянного ответа и получает единственную запись. |

Реальный браузерный проход использует `LocalService`, сквозное хранение и реальный транспорт HTTP. Успешный и неполный отчёты строит штатный replay. Спорный отчёт строится тем же pipeline из действующей синтетической фикстуры E9. Mock в браузерных тестах используется для управляемых сбоев и длинного текста. Счётчик новых запросов анализа в проходах чтения, проверки и экспорта равен нулю.

Из корня репозитория с установленными зависимостями прототипа запустите:

```sh
.venv/bin/python scripts/check_repository.py
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python -m unittest discover -s prototype/tests -q
node --test prototype/tests/test_web_*.cjs
.venv/bin/python scripts/check_cli_replays.py
```

Для браузерной проверки нужны Playwright и совместимый Chrome/Chromium. Можно использовать уже установленный Playwright через `PLAYWRIGHT_MODULE` и Chrome через `CHROMIUM_PATH`. После `npm install --prefix /tmp/nanimai-browser playwright@1.62.1` ими, например, будут `/tmp/nanimai-browser/node_modules/playwright` и путь к Chrome. Если `CHROMIUM_PATH` не задан, используйте Chromium из `playwright install chromium`. Для записи нужен ffmpeg Playwright.

```sh
# Первый терминал
.venv/bin/python docs/reviews/vanya-night-fixtures.py /tmp/nanimai-v11-check

# Второй терминал
node docs/reviews/vanya-night-browser.cjs /tmp/nanimai-v11-check
```

Скрипт создаёт отдельное хранилище. Каждый новый прогон требует нового имени каталога. Для записи поднимите такой же сервис в новом пустом каталоге, создайте папку для медиа и запустите:

```sh
.venv/bin/python docs/reviews/vanya-night-fixtures.py /tmp/nanimai-v11-record
node docs/reviews/vanya-night-record.cjs /tmp/nanimai-v11-record /tmp/nanimai-v11-media
```

Вторую команду запускайте в отдельном терминале. SHA берётся из checkout и записывается в видео и имена файлов. Видео, HTML и PDF передаются отдельно от Git. В live-режиме тестов не было. Сверка с исходным комплектом SVG ожидает доступ к файлам на компьютере Григория. Интерфейс использует существующую оболочку Nanimai и её компоненты.
