# Совместная работа

Владелец сам приглашает участников в приватный репозиторий. Заполните роли и выберите одну задачу с проверяемым результатом.

```sh
git switch main
git pull --ff-only
git switch -c feature/short-task-name
# изменения
python3 scripts/check_repository.py
git add <нужные-файлы>
git commit -m "Кратко описать результат"
git push -u origin HEAD
```

Открыть PR в main. Для агентов — префикс `codex/`. Не делать force-push общей ветки. Перед слиянием проверить разницу, результаты соответствующих тестов и новый сквозной путь. Шаблон PR напоминает об этом; branch protection в этой подготовке не устанавливалась.

Исходный код в services — база Nanimai, а не результат хакатона. В PR отмечать новый вклад. Копии сервисов имеют разные версии Python и отдельные lock-файлы; не объединять зависимости механически. Vendor deployment workflows не включены.

Секреты и реальные резюме не коммитить. Для HR-демо использовать синтетические данные. Происхождение и ограничения компонентов — THIRD_PARTY_NOTICES.md. Отсутствующие сервисы и заглушки называть явно. Изменения поведения модели проверять на отложенных примерах, не только удачной демонстрации.
