# CLI: одно CV → рейтинг вакансий

Первый технический срез без UI и ATS. Python 3.12+; реальный Certum core использует Python 3.12. Docker-образ автономного CLI собран и проверен 13 ноября на этом Mac (Linux arm64 внутри OrbStack). [Архитектура](../docs/15-architecture.md) отделяет текущие возможности от будущих.

## Установка и локальная демонстрация

Из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r prototype/requirements.lock.txt
python -m unittest discover -s prototype/tests -v
python -m prototype demo
python -m prototype demo --scenario disputed
```

Демо создаёт **рукописный синтетический replay**, сеть не вызывается. Встроены три вакансии: подтверждённое соответствие, неизвестный Java и недостаточный явно указанный стаж SQL. Результат — report.json, requirements.csv, report.md в отдельной новой папке. Они не являются доказательством качества модели.

Для консультации два воспроизводимых примера (оба без сети):

- `demo`: job-001 имеет L/H=100/100, рекомендация `review_top`; Java неизвестен, обязательный стаж SQL явно не выполнен.
- `demo --scenario disputed`: у job-001 составное обязательное требование Python и Go подтверждено частично; L/H=50/50, рекомендация `clarify` и вопрос об опыте Go. Это ручная иллюстрация политики partial=0.5, не вывод модели и не обещание такого же извлечения в live. Вместе примеры показывают все четыре статуса.

Markdown объясняет сортировку, показывает обработано/всего и перечисляет неоценённые вакансии при остановке. Неполный набор не превращается в рекомендацию отказа.

requirements.lock.txt фиксирует проверенные версии CLI (Python 3.13/macOS); совместимость на ноутбуках команды и с отдельным окружением core Python 3.12 ещё нужно проверить. requirements.txt задаёт диапазоны для осознанного обновления, не для автоматического обхода конфликтов.

Локально проверить чтение своего документа, не отправляя его в модель:

```sh
python -m prototype inspect '/полный/путь/к/документу.docx'
```

Выводит только число извлечённых символов. Форматы txt/md UTF-8, PDF с текстовым слоем, DOCX с абзацами и таблицами. Ограничения: 5 MB, 60 000 символов, 100 страниц PDF; OCR отсутствует. Колонтитулы/вложенные таблицы/изображения DOCX не гарантированы. Пустая страница PDF прекращает обработку, чтобы не скрывать возможную потерю сведений.

## Первый настоящий вызов — встроенный пример

Первый live Luna успешно выполнен 13 ноября на встроенных данных. Когда OPENAI_API_KEY добавлен локально в окружение:

```sh
python -m prototype demo --live --model gpt-6-luna --budget 1
```

Это платный вызов на встроенном вымышленном тексте без личности. Sol сравнивается отдельно:

```sh
python -m prototype demo --live --model gpt-6.1-sol --budget 1
```

Не передавать ключ аргументом команды или в чат. `.env` автоматически не загружается; `.env.example` содержит только названия. Ключ не нужен для тестов/replay. Автоматической смены модели нет. Luna проверена на этом аккаунте; Sol не проверена.

Резерв стоимости по умолчанию $1 на процесс, явный максимум $5; полный баланс $74 не расходуется автоматически. До 50 вызовов, без повторов SDK, 90 секунд на запрос. Резерв консервативный, не счёт провайдера. Одновременные процессы не имеют общего лимита — массовые запуски координирует Григорий. Тарифы и ограничения приведены в архитектуре.

## Реальные файлы и Certum

```sh
python -m prototype run \
  --resume '/полный/путь/к/резюме.pdf' \
  --jobs '/полный/путь/к/папке-вакансий' \
  --model gpt-6-luna --budget 1
```

Один CV, от 1 до 20 вакансий. Скрытые файлы пропускаются; каждый другой файл должен иметь поддерживаемый формат. Имена файлов не идут в API: вакансии получают job-001 и далее по отсортированному списку. Пока соответствие id↔файл определяется этим порядком; локальный manifest — следующая доработка.

Команда **не заработает только после добавления OpenAI-ключа**. Нужны:

1. Настоящий certum_core Глеба из certum-assistant в Python 3.12; зависимости брать из его pyproject/lock.
2. Локальные модели, загруженные штатной командой core `python -m certum_core.detectors.models`. При обработке CV скрытого скачивания нет.
3. Мигрированный PostgreSQL с ролью приложения, подготовленным tenant и его зашифрованным ключом. Отдельное окружение проекта, не личная production-база.
4. Переменные CERTUM_DATABASE_URL, CERTUM_MASTER_KEY, CERTUM_TENANT_ID; при необходимости CERTUM_DETECTORS_MODELS_DIR.
5. Проверка разрешённого состава данных и качества защиты до внешней передачи. Адаптер написан по фактическому API core; полного интеграционного прогона ещё не было.

CLI не устанавливает core и не поднимает базу. Нет regex-замены вместо Certum и флага обхода проверки для своих файлов. Остаточные находки, отсутствие NER, ошибка базы или ключа останавливают передачу. Код не использует Claude relay Глеба: после локальной защиты обращается к выбранному OpenAI API.

Псевдонимизация не гарантирует отсутствия косвенной идентификации. Настройка реального контура остаётся работой Григория, не задачей Егора/Вани по умолчанию.

## Результат и ошибки

- report.json: факты, требования, статусы, обоснования, вопросы, числа, режим и usage для live.
- requirements.csv: таблица оценённых требований; формулы из недоверенного текста экранируются.
- report.md: читаемый рейтинг и подробности по вакансии.

Статусы: full / partial / fail / unknown. Баллы считает код. Политика черновая: веса 3 обязательным, 1 остальным; partial=0.5. L/H — границы при недостающих данных, coverage — известность, не вероятность найма.

Выход 0 — полный отчёт/успешное чтение; 2 — ошибка или неполный рейтинг. Ошибка одной оценки прекращает следующие вызовы; успешные пары сохраняются, итог incomplete. Ошибка facts после защиты сохраняет пустой incomplete-отчёт; ошибки входа/первичной защиты завершают запуск без отчёта. В ошибках сохраняется stage (facts, facts_validation, requirements, requirements_validation, evaluation, evaluation_validation). Текст исключения скрывается, чтобы не вывести данные и секреты; не включать полное SDK-логирование ради диагностики.

Обязательность структурно привязана к требованию: mandatory_quote включает quote целиком и содержит минимум 8 символов. Для заголовка требуется непрерывная цитата от заголовка до требования. Это консервативная проверка, а не доказательство смысла обязательности: модель может ошибиться с контекстом или отрицанием. Точные дубли text+quote отклоняются. Парафразы-дубли и смысловая релевантность фактов автоматически не гарантируются.

## Docker для автономного CLI

Dockerfile использует Python 3.13 и закреплённые зависимости CLI. В образ не включены Certum, PostgreSQL и модели NER: команда run с реальными файлами не является готовым контейнерным путём. Это упаковка replay и встроенного synthetic live; финальный защищённый контур ещё нужно собрать в Python 3.12. Для одного процесса Compose не требуется; текущие compose-файлы в services относятся к старым сервисам, не к этому CLI.

Из корня проекта на macOS/Linux с запущенным Docker:

```sh
docker build -t recruiter-cli:local .
mkdir -p data/private/prototype-runs
docker run --rm --network none --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$(pwd)/data/private/prototype-runs,dst=/app/data/private/prototype-runs" \
  recruiter-cli:local demo
docker run --rm --network none --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$(pwd)/data/private/prototype-runs,dst=/app/data/private/prototype-runs" \
  recruiter-cli:local demo --scenario disputed
```

Отчёты остаются на хосте в data/private/prototype-runs. Процесс заканчивается сам; досрочная остановка — Ctrl+C, контейнер удаляется благодаря --rm. Команды рассчитаны на POSIX shell; на Windows использовать WSL. Ключи не передавать при сборке. Для отдельно разрешённого synthetic live заменить --network none на -e OPENAI_API_KEY (значение берётся из окружения хоста) и передать demo --live --model gpt-6-luna --budget 1. Автоматический live при запуске образа не выполняется.

13 ноября сборка и оба replay подтверждены на Mac владельца с OrbStack, Linux arm64; это не проверка на втором компьютере. Базовый Python закреплён digest. Состав /app/prototype проверен внутри образа: только 9 модулей, lock и test_core.py. Никакие .env, исходные документы и отчёты в образ не включены. Digest базы не фиксирует внешние зависимости Certum, которые в этот образ не входят.

## Проверка настоящего Certum отдельно от OpenAI

13 ноября выполнен `scripts/certum_smoke.py`: Python 3.12.16, отдельная копия core и его uv.lock, новая PostgreSQL на 127.0.0.1:55439, отдельный tenant/vault, Slovnet/Navec с проверкой хешей. Вымышленные ФИО/телефон/email заменены, исходящий текст проверен, сырой contact#123 отклонён. OpenAI не вызывается. Повтор на подготовленном Mac:

```sh
data/private/certum-sandbox/core/.venv/bin/python scripts/certum_smoke.py \
  --env-file data/private/certum-sandbox/core/.env \
  --tenant-file data/private/certum-sandbox/tenant-id \
  --models-dir data/private/certum-sandbox/models
```

Закрытый каталог не входит в Git и отсутствует у других участников. Настройка и остановка — в docs/17-certum-local-setup.md. Не устанавливать lock CLI поверх lock core: у них разные версии OpenAI SDK. Это проверка адаптера, не общий live end-to-end и не доказательство полной анонимности.

review_top означает «проверьте верхние позиции». review_none_fit возможен при полном наборе и отмеченном моделью нарушении обязательного критерия у каждой вакансии. Это гипотеза для проверки рекрутером, окончательный none_fit CLI не выдаёт. Равные оценки имеют одинаковое место; рекомендация учитывает всю группу первого места. Кадровое решение принимает человек.

## Ограничения

Нет UI, БД приложения, нескольких CV за один запуск, OCR, HH, фоновых работников, повторов/возобновления, редактирования требований и эталона качества. Дословная цитата не гарантирует правильной интерпретации. Первое настоящее сравнение Luna/Sol и Certum end-to-end ещё впереди. Не описывать их как проверенные.

Остановка: Ctrl+C; постоянного сервера нет. Результаты удалять по выбранным папкам запусков, не затрагивая другие материалы. Глобальные зависимости и настройки не меняются.
