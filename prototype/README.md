# Локальное приложение и CLI: одно CV → рейтинг вакансий

Текущий runtime — Python 3.13, UI/HTTP-сервис и собственный privacy_core без certum_core/БД. [Быстрый запуск UI, Docker и приёмка](../docs/28-local-app-runbook.md). История и решения HR сохраняются локально; replay/mock работают без платного API.

```sh
.venv/bin/python -m prototype serve
```

Открыть `http://127.0.0.1:8765`. Для защищённого mock нужны подготовленные публичные NER-модели. `.env` не загружается автоматически. Ниже команды CLI и исторические подробности его проверки; фактическая готовность новой сборки — в [журнале качества](../docs/04-quality.md).

## Установка и локальная демонстрация

Из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r prototype/requirements.lock.txt
python -m unittest discover -s prototype/tests -v
python -m prototype demo
python -m prototype demo --scenario disputed
```

Демо создаёт **рукописный синтетический replay**, сеть не вызывается. Встроены три вакансии: подтверждённое соответствие, неизвестный Java и недостаточный явно указанный стаж SQL. Результат — report.json, requirements.csv, report.md в отдельной новой папке. Они не являются доказательством качества модели.

Для консультации два воспроизводимых примера (оба без сети):

- `demo`: job-001 имеет L/H=100/100, рекомендация `review_top`; Java неизвестен, обязательный стаж SQL явно не выполнен.
- `demo --scenario disputed`: у job-001 составное обязательное требование Python и Go подтверждено частично; L/H=50/50, рекомендация `clarify` и вопрос об опыте Go. Это ручная иллюстрация политики partial=0.5, не вывод модели и не обещание такого же извлечения в live. Вместе примеры показывают все четыре статуса.

Markdown объясняет сортировку, показывает обработано/всего и перечисляет неоценённые вакансии при остановке. Неполный набор не превращается в рекомендацию отказа.

requirements.lock.txt фиксирует единый CLI/privacy runtime. requirements.protected.lock.txt ссылается на него, отдельного Certum lock больше нет. Независимый запуск на втором физическом компьютере передан Егору: Ваня ночью недоступен.

Локально проверить чтение своего документа, не отправляя его в модель:

```sh
python -m prototype inspect '/полный/путь/к/документу.docx'
```

Выводит только число извлечённых символов. Форматы txt/md UTF-8, PDF с текстовым слоем, DOCX с абзацами и таблицами. Ограничения: 5 MB, 60 000 символов, 100 страниц PDF; OCR отсутствует. Вложенные таблицы читаются; текстовые колонтитулы, фигуры и неподдержанные текстовые структуры отклоняются с диагностикой. Пустая страница PDF прекращает обработку, чтобы не скрывать возможную потерю сведений.

## Первый настоящий вызов — встроенный пример

Первый live Luna успешно выполнен 13 ноября на встроенных данных. Когда OPENAI_API_KEY добавлен локально в окружение:

```sh
python -m prototype demo --live --model gpt-6-luna --budget 1
```

Это платный вызов на встроенном вымышленном тексте без личности. Sol сравнивается отдельно:

```sh
python -m prototype demo --live --model gpt-6.1-sol --budget 1
```

Не передавать ключ аргументом команды или в чат. `.env` автоматически не загружается; `.env.example` содержит только названия. Ключ не нужен для тестов/replay. Автоматической смены модели нет. Luna проверена на этом аккаунте; Sol не проверена.

Резерв стоимости по умолчанию $1 на процесс, явный максимум $5; полный баланс $74 не расходуется автоматически. До 50 вызовов, без повторов SDK, 90 секунд на запрос. Резерв консервативный, не счёт провайдера. Одновременные процессы не имеют общего лимита — массовые запуски координирует Григорий. Тарифы и ограничения приведены в архитектуре.

## Реальные файлы и privacy_core

```sh
python -m prototype run \
  --resume '/полный/путь/к/резюме.pdf' \
  --jobs '/полный/путь/к/папке-вакансий' \
  --model gpt-6-luna --budget 1
```

Один CV, от 1 до 30 вакансий. Скрытые файлы пропускаются; каждый другой файл должен иметь поддерживаемый формат. Имена файлов не идут в API: id основан на SHA256 извлечённого текста с различением одинаковых документов; связь с именем хранится в локальном manifest.

До запуска `run` нужны OpenAI-ключ в окружении, установленные публичные модели и разрешение на внешний состав данных. Реальные CV кейса пока во внешний API не передавать: эксперт отослал вопрос к техническому специалисту.

```sh
python -m prototype.privacy_core.prepare
python scripts/privacy_smoke.py
python scripts/privacy_smoke.py --model-mock
```

Это наш модуль `prototype/privacy_core/`, не переименованный Certum. Python 3.13, открытые Slovnet/Navec, без PostgreSQL/tenant/master key. Каталог моделей — `data/private/privacy-models` или `PRIVACY_MODELS_DIR`; веса проверяются по закреплённым SHA256. Скачивание выполняется только отдельной командой подготовки. При отсутствии NER/ошибке/остаточной находке сеть блокируется; обход для файлов отсутствует. Псевдонимизация не гарантирует анонимности. Известные ограничения и источник технологии — [docs/24](../docs/24-local-privacy-core.md).

## Результат и ошибки

- report.json: факты, требования, статусы, обоснования, вопросы, числа, режим и usage для live.
- requirements.csv: таблица оценённых требований; формулы из недоверенного текста экранируются.
- report.md: читаемый рейтинг и подробности по вакансии.

Дополнительные поля JSON: verification/presentation/unprocessed/events. Для экрана и черновика менеджеру использовать presentation: только цитаты и вопросы по требованиям; произвольный текст модели остаётся явно непроверенным. `complete` показывает полноту обработки, `verification.final_allowed=false` — отсутствие итоговой проверки человеком. E3/E4 теперь подключены: evidence_check, requirements_draft и requirements_review; structure_ok подтверждает структуру, но не смысл. Для пользовательских файлов локальный `inputs.manifest.json` связывает стабильный id по хешу текста с именем; имена в модель не передаются.

Комплект отчёта пишется в закрытый временный каталог и публикуется одним rename после успешного сохранения всех файлов. В protected режиме публикация происходит после успешного закрытия локального контекста защиты. Непригодный output и больше 30 вакансий отклоняются до модели; symlink-файлы не принимаются. Ограничения каталогов относятся к локальному вводу; HTTP-транспорт обязан иметь собственную изоляцию загрузок.

Проверочные ошибки ответа (`model_invalid`) не мешают обработать остальные вакансии; privacy/budget/network/неизвестный отказ останавливает новые запросы. `unprocessed` указывает причины пропусков. `--deadline 300` ограничивает асинхронные стадии, не принудительно прерывает синхронный парсер/warmup; готовая часть сохраняется, если close/export успешны. `RunControl.cancel()` останавливает новые запросы, включая отмену во время scan. Уже отправленный запрос может быть оплачен. Для close/cleanup предусмотрено отдельное окно 30 с.

Лимиты ответа по стадиям — 2048–16000 токенов в зависимости от размера входа/числа требований. Это не замер оптимальной ёмкости: обрезанный/невалидный ответ становится явной ошибкой, требования молча не удаляются. Usage, консервативный reserved и остаток резерва показываются раздельно; баланс провайдера неизвестен. Факты извлекаются один раз на запуск; до трёх вакансий обрабатываются параллельно. Повторное открытие сохранённого отчёта не вызывает модель.

Статусы: full / partial / fail / unknown. Баллы считает код. Политика черновая: веса 3 обязательным, 1 остальным; partial=0.5. L/H — границы при недостающих данных, coverage — известность, не вероятность найма.

Выход 0 — полный отчёт/успешное чтение; 2 — ошибка или неполный рейтинг. Ошибка проверки ответа по одной вакансии позволяет продолжить остальные; глобальный отказ останавливает следующие вызовы. Успешные пары сохраняются, итог incomplete. Ошибка facts после защиты сохраняет пустой incomplete-отчёт; ошибки входа/первичной защиты завершают запуск без отчёта. В ошибках сохраняется stage (facts, facts_validation, requirements, requirements_validation, evaluation, evaluation_validation). Текст исключения скрывается, чтобы не вывести данные и секреты; не включать полное SDK-логирование ради диагностики.

Обязательность структурно привязана к требованию: mandatory_quote включает quote целиком и содержит минимум 8 символов. Для заголовка требуется непрерывная цитата от заголовка до требования. Это консервативная проверка, а не доказательство смысла обязательности: модель может ошибиться с контекстом или отрицанием. Точные дубли text+quote отклоняются. Парафразы-дубли и смысловая релевантность фактов автоматически не гарантируются.

## Docker для автономного CLI

Dockerfile использует Python 3.13 и закреплённые зависимости CLI. В образ входят собственный privacy_core и два публичных архива NER в /opt/privacy-models с проверкой хешей. Certum и PostgreSQL не нужны. При сборке выполняются локальный privacy smoke и настоящий SDK с mock transport; они не являются live-моделью. Для одного процесса Compose не требуется; текущие compose-файлы в services относятся к старым сервисам, не к этому CLI.

Из корня проекта на macOS/Linux с запущенным Docker:

```sh
docker build -t recruiter-cli:local .
mkdir -p data/private/prototype-runs
docker run --rm --network none --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$(pwd)/data/private/prototype-runs,dst=/app/data/private/prototype-runs" \
  recruiter-cli:local demo
docker run --rm --network none --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$(pwd)/data/private/prototype-runs,dst=/app/data/private/prototype-runs" \
  recruiter-cli:local demo --scenario disputed
```

Отчёты остаются на хосте в data/private/prototype-runs. Процесс заканчивается сам; досрочная остановка — Ctrl+C, контейнер удаляется благодаря --rm. Команды рассчитаны на POSIX shell; на Windows использовать WSL. Ключи не передавать при сборке. Для отдельно разрешённого synthetic live заменить --network none на -e OPENAI_API_KEY (значение берётся из окружения хоста) и передать demo --live --model gpt-6-luna --budget 1. Автоматический live при запуске образа не выполняется.

Сборка требует сети для Python-пакетов и публичных весов; runtime smoke и replay запускаются без сети. Ключи, .env, документы и данные не входят в build context. Фактические проверки — docs/04-quality.md; другой компьютер не считается проверенным автоматически.

Проверить защищённый путь в контейнере без API:

```sh
docker run --rm --network none --entrypoint python recruiter-cli:local \
  scripts/privacy_smoke.py --models-dir /opt/privacy-models --model-mock
```

## Проверка доказательств и маскирования

В отчёте сохраняются состояния E3/E4; спорные цитаты имеют контекст. Непривязанный структурно маркер обязательности получает обычный вес 1, не влияет как жёсткое условие и перечисляется в `score_review.excluded_mandatory_ids`. Исходное предложение модели остаётся для проверки. Числовая формула не заменяет человеческое решение.

`privacy.professional_information_may_be_hidden` предупреждает, что NER заменил ORG, среди которых могут быть технологии. Например, Rust иногда считается организацией в одном документе и навыком в другом: без сверки локального оригинала это не подтверждённый пробел кандидата. [Полные ограничения](../docs/24-local-privacy-core.md).

review_top означает «проверьте верхние позиции». review_none_fit возможен при полном наборе и отмеченном моделью нарушении обязательного критерия у каждой вакансии. Это гипотеза для проверки рекрутером, окончательный none_fit CLI не выдаёт. Равные оценки имеют одинаковое место; рекомендация учитывает всю группу первого места. Кадровое решение принимает человек.

## Ограничения

Нет нескольких CV за один запуск, OCR, HH, многопользовательской авторизации, автоматического возобновления платных запросов и редактора требований. Есть локальный файловый store, один фоновый анализ и синтетические разметки E6; они ещё не доказывают качество модели. Дословная цитата не гарантирует правильной интерпретации. Сравнение Luna/Sol, protected live нового модуля и качество защиты на типичных реальных CV не проверены. Не описывать их как проверенные.

Остановка: Ctrl+C; постоянного сервера нет. Результаты удалять по выбранным папкам запусков, не затрагивая другие материалы. Глобальные зависимости и настройки не меняются.

Если CDN моделей отвечает тайм-аутом, сборка с заранее полученными публичными весами:

```sh
python -m prototype.privacy_core.prepare --from-dir data/private/privacy-models --dir runtime/privacy-models
docker build --build-arg PRIVACY_MODEL_SOURCE=local -t recruiter-cli:local .
```

Размеры/SHA256 проверяются до копирования и в образе. Нужны только два публичных архива, не закрытая копия Certum. Этот путь проверен локально; прямая загрузка в текущей сети давала TimeoutError. [Подробности](../docs/24-local-privacy-core.md).
