# Мультиагентная система для этого хакатона

Проверено 6 ноября 2026 года по первичным репозиториям, инструкциям и конфигурациям. Это сравнение; установщики перечисленных систем не запускались. Приложение под кейс пока не разрабатывается.

## Кандидаты

| Система | Сильная сторона | Что учитывать у нас |
|---|---|---|
| [Superpowers](https://github.com/obra/superpowers) | Планирование, реализация, отладка, тесты и независимое ревью; есть поддержка Codex App | В полном режиме создаёт исполнителя и проверяющего для каждой задачи. Для наших лимитов полезнее executing-plans: основная сессия реализует план, отдельный агент проверяет итог |
| [Oh My Codex](https://github.com/Yeachan-Heo/oh-my-codex) | Оркестрация команды, tmux/worktrees, состояние задач и учёт использованных токенов | Авторы ориентируются на Codex CLI на macOS/Linux и предупреждают о более слабой поддержке Codex App. Установка CLI глобальная, setup можно ограничить проектом |
| [GSD Core](https://github.com/open-gsd/gsd-core) | Этапы исследования, планирования, реализации и проверки; отдельные контексты; лимит параллельности и модельные профили | Документирована локальная установка. Нужна проверка с нашей версией Codex и явная настройка моделей; дефолтный рабочий процесс может быть избыточен для короткого хакатона |
| [BMAD Method](https://github.com/bmad-code-org/BMAD-METHOD) | Продуктовые и инженерные роли: аналитик, PM, архитектор, UX, разработчик | Stable-линия v6.12, а main — v7 preview alpha. Для короткого соревнования полный набор процедур может занять слишком много времени |

Наличие многих ролей не гарантирует параллельное исполнение: некоторые системы задают процесс и персоны, а запуск отдельных агентов обеспечивает сам Codex.

## Предлагаемая конфигурация

Для работы в текущем приложении: **нативные субагенты Codex + процесс Superpowers в экономном режиме**. Для отдельного эксперимента с терминальной командой агентов: OMX. Это инженерная рекомендация по изученным возможностям, не результат сравнительного бенчмарка.

Роли в текущем режиме:

1. Главная сессия — координация, архитектура, реализация и принятие результата.
2. Исследователь — `gpt-6-luna`, `high`; короткая самостоятельная задача, только чтение.
3. Ревьюер — `gpt-6.1-sol`, `medium`; одно ревью существенного результата, только чтение.

Работают главный агент и максимум один помощник одновременно. Не больше двух новых помощников на ограниченную задачу. Без вложенного порождения агентов, полного копирования истории и автоматического перехода к платным API. Пользовательские правила из AGENTS.md имеют приоритет перед процедурами пакета.

Ограничение параллельности — не жёсткий лимит токенов: последовательные запуски тоже расходуют подписку. Проценты экономии не измерены.

## Изоляция проекта

Codex документирует настройки в `.codex/config.toml` и проектные роли в `.codex/agents/`. Проектные настройки загружаются только для доверенного проекта. Это позволяет ограничить будущую конфигурацию данной папкой; сам факт установки плагина через общий каталог не доказывает такую изоляцию.

Для выбора готового пакета перед установкой проверить его файловые изменения, зафиксировать версию, сохранить существующий AGENTS.md и выполнить маленький тест работы исследователя и ревьюера. Проверка конфигурации сама по себе не подтверждает работу авторизации или запуск модели.

## Важные находки

- Старый [gsd-build/get-shit-done](https://github.com/gsd-build/get-shit-done) архивирован; README перенаправляет на Open GSD / GSD Core.
- У GSD Core в документации указан минимум Codex CLI 0.130.0; локально найден 0.166.0-alpha.6. Сравнение версий проходит, совместимость полного сценария не проверялась.
- Документация GSD Core прямо отмечает, что предупреждения об остатке контекста для Codex сейчас не поддерживаются. Нельзя переносить обещания возможностей Claude Code на Codex.
- В примерах OMX встречается `--madmax`: это отключение обычных механизмов sandbox и подтверждений. Для нашего эксперимента такой флаг не нужен.
- Совместная установка нескольких полных методологий усложняет правила. Выбрать одну и сохранить небольшое число активных ролей.
