# Мультиагентный стенд хакатона

Актуальные персональные инструкции: [Егор / Claude + Opus](docs/team/egor.md), [Ваня / Codex](docs/team/vanya.md). Общие роли и первые задачи: [план команды](docs/14-team-kickoff.md). Кейс получен, разрешён CLI-прототип; учебный пример ниже — только историческая проверка установки.

Установлены Superpowers 7.0.2 и проектные роли Codex. Область установки — эта папка. Глобальные настройки Codex установщик не изменяет. Авторизация CLI использует существующий вход ChatGPT; модельные API-ключи не нужны.

## Запуск в приложении

Открой новую сессию Codex в этой папке, чтобы она обнаружила добавленные роли и навыки. Вставь:

> Используй мультиагентный режим этого проекта. Прочитай AGENTS.md и MULTIAGENT_START.md. Главный агент ведёт задачу и пишет код; hackathon_scout исследует отдельный вопрос; hackathon_reviewer проверяет готовый результат. Одновременно один помощник, без вложенных агентов. Для маленьких задач работай сам. Задание: [описание].

Условие и ответы эксперта уже зафиксированы в docs/12-expert-answers.md; текущая архитектура — docs/15-architecture.md. Учебный пример experiments/agent-smoke повторять не обязательно.

## Запуск в терминале

Из папки проекта:

```sh
bash scripts/start-agents.sh
```

Откроется Codex с основной моделью Sol / medium. Для сложных архитектурных решений можно продолжать работу основной моделью в приложении. Скрипт проверяет вход через ChatGPT, не создаёт новый аккаунт и не меняет провайдера.

## Кто что делает

| Роль | Модель | Ответственность |
|---|---|---|
| Главная сессия | Модель текущего чата; в launcher Sol / medium | План, архитектура, код, интеграция и принятие результата |
| hackathon_scout | gpt-6-luna / high | Читает ограниченный набор файлов и возвращает выводы |
| hackathon_reviewer | gpt-6.1-sol / medium | Ищет ошибки, нарушения доступа и регрессии |

Две вспомогательные роли не запускаются одновременно. Лимит открытых помощников задан конфигурацией; лимит двух запусков на задачу и запрет вложенных агентов заданы инструкциями. Это не жёсткий лимит токенов. Все модельные вызовы расходуют подписку.

## Режим Superpowers

Короткий бриф → план → executing-plans → одно независимое ревью → проверки. Библиотека навыков доступна локально; не нужно загружать весь каталог в каждый запрос. Полный режим subagent-driven-development с новым исполнителем и проверками на каждую мелкую задачу не является режимом по умолчанию.

## Проверка и повтор эксперимента

Учебный бриф: experiments/agent-smoke/BRIEF.md. Протокол: experiments/agent-smoke/RESULT.md. Полные события диагностического запуска находятся в artifacts/ и исключены из Git.

В новой сессии можно попросить: «Проведи учебный тест по experiments/agent-smoke/PROMPT.md». После исправления учебного примера нормальный результат ревью — отсутствие прежних ошибок; их не нужно придумывать заново.

## Версия и перенос

Superpowers зафиксирован на коммите `22f0b463e7a5e579904dd6211a520321035526f7`. Исходники и MIT-лицензия лежат в vendor/superpowers. Исходники исключены из Git; при переносе на другой компьютер загрузить их перед запуском setup:

```sh
git clone https://github.com/obra/superpowers.git vendor/superpowers
git -C vendor/superpowers checkout 22f0b463e7a5e579904dd6211a520321035526f7
python3 scripts/setup_agents.py
```

Установщик проверяет ревизию и отказывается перезаписывать отличающиеся настройки. Проектные .codex и .agents должны загружаться доверенным Codex-проектом. Для отключения сохранить резервную копию и убрать созданные .codex/config.toml, две роли hackathon_* и ссылки навыков этого проекта; глобальные economy_* роли остаются отдельной настройкой владельца.
