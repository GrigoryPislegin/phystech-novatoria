# AI-рекрутер · объяснимый рейтинг вакансий

**Одно резюме + до 30 вакансий → рейтинг, основания и вопросы кандидату.** Загрузите PDF с текстовым слоем, DOCX, TXT или MD и нажмите «Запустить анализ». История находится отдельно; результат открывается автоматически. Основная продуктовая модель — OpenAI `gpt-6-luna`. Резюме разбирается один раз; требования и сопоставление каждой вакансии возвращаются одним ответом. До 12 вакансий обрабатываются параллельно в общем бюджете.

## Быстрый запуск в Docker

Нужны Docker Engine/Desktop и ключ OpenAI с доступом к Luna. Сборка скачивает Python-зависимости и два открытых NER-артефакта с проверкой SHA-256; исходные документы и ключ в образ не попадают.

```sh
docker build -t recruiter:local .
```

Для сборки из поставки с уже приложенными публичными весами:

```sh
docker build --build-arg PRIVACY_MODEL_SOURCE=local -t recruiter:local .
```

Создайте локальный файл `model.env` с единственной строкой `OPENAI_API_KEY=ваш_ключ`. Не добавляйте его в Git. На macOS/Linux ограничьте права: `chmod 600 model.env`.

```sh
docker run -d --name recruiter \
  -p 127.0.0.1:8765:8765 \
  --env-file model.env \
  -v recruiter-data:/app/data \
  recruiter:local serve --host 0.0.0.0 --port 8765 \
  --state-dir /app/data/private/local-app --allow-live
```

Откройте **http://127.0.0.1:8765**. Выберите резюме и вакансии, нажмите одну кнопку. Платный запрос начинается только после запуска пользователем. Лимит одного запуска в UI — $1; оценка стоимости зависит от учтённых токенов, это не выписка провайдера.

Остановка: `docker stop recruiter`. Повторный запуск: `docker start recruiter`. Удаление контейнера: `docker rm -f recruiter`; именованный том с историей сохраняется. Для публичного доступа нужен HTTPS-прокси с аутентификацией и `--public-origin https://ваш-адрес`; не публикуйте порт приложения напрямую. Инструкция сервера — в [runbook](docs/28-local-app-runbook.md).

## Что находится в отчёте

- Краткое сравнение всех вакансий, раскрытые основания первых трёх вариантов и подробности остальных по нажатию.
- Баллы по единой политике, покрытие требований, группы навыков с весами. Радар показывается только при достаточном числе подтверждённых групп; иначе используются полосы.
- Четыре исходных статуса: полное, частичное, явное несоответствие и отсутствие сведений. Спорные основания выделяются отдельно.
- Дословные цитаты из обоих документов, вопросы кандидату, условия работы, сравнение вакансий и HTML-выжимка менеджеру.
- Локальное восстановление скрытых значений в отображении. Служебные метки не заменяют названия навыков в итоговом интерфейсе.

Модель извлекает факты и сопоставляет смысл. **Числа считает Python:** обязательная группа получает 75 баллов, прочая — 25; единственная группа получает 100. Полное соответствие даёт весь вес, частичное — половину. Повторы объединяются; непроверяемое основание не добавляет баллов. Неизвестность не означает отсутствие навыка. Рейтинг и покрытие следует читать вместе. Эти веса — политика команды, не вероятность найма.

## Архитектура и данные

```text
Документы → локальный разбор → privacy_core (Slovnet/Navec + правила)
          → факты и профиль резюме (1 запрос Luna)
          → требования + оценка каждой вакансии (2 запроса, до 3 вакансий параллельно)
          → проверка цитат/ссылок → детерминированный скоринг → отчёт и история
```

Короткие модельные ссылки восстанавливаются локально до проверки цитат. Ошибочный ответ может получить один ограниченный повтор; исходные документы повторно в открытом виде не отправляются. Внешний сервис — OpenAI API; NER работает локально. Веса нужны только при сборке, при запуске загрузок моделей нет. Отчёты, подготовленные источники и таблицы восстановления остаются в локальном томе, имеют отдельные права доступа. Это псевдонимизация, а не гарантия полной анонимности. [Подробная архитектура](docs/15-architecture.md), [privacy_core](docs/24-local-privacy-core.md), [права компонентов](THIRD_PARTY_NOTICES.md).

## Два воспроизводимых сценария без ключа

Они проверяют расчёт и обработку неопределённости; **это заранее подготовленные ответы, не оценка качества Luna**.

```sh
docker run --rm --network none recruiter:local demo --scenario success
docker run --rm --network none recruiter:local demo --scenario disputed
```

1. **Подходящая вакансия:** встроенное резюме с Python/SQL и три вакансии. Ожидается 3/3, первая вакансия подтверждает Python/SQL, неизвестный Java отличается от явно недостаточного стажа SQL.
2. **Спорное требование:** составное требование Python/Go подтверждено частично. Ожидаются partial, вопрос для уточнения и сохранённые цитаты; неизвестный Go не превращается в доказанное несоответствие.

## Проверки и ограничения

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install -r prototype/requirements.lock.txt
.venv/bin/python -m prototype.privacy_core.prepare --dir data/private/privacy-models
.venv/bin/python -m unittest discover -s prototype/tests -q
node --test prototype/tests/test_web_*.cjs
```

Проверки включают реальные локальные NER-веса, отмену/сроки/бюджет, одновременную обработку, повтор запросов, историю, цитаты, обязательность и защиту отображения. Актуальные измерения реальных запусков и ограничения — в [журнале качества](docs/04-quality.md); итоговая приёмка 30 вакансий оформляется отдельно от синтетических тестов.

OCR нет; сканы без текстового слоя не поддерживаются. Лимиты: 5 МБ на файл, 20 МБ суммарно. Качество смысловой оценки зависит от исходных документов и модели; наличие точной цитаты само по себе не доказывает правильность интерпретации. При сбое отдельной оценки сохраняются пригодные результаты с явным указанием неполного набора. Недоступность провайдера, неверный ключ, отмена или повреждённый ввод могут завершить запуск ошибкой — готовый ответ не подменяется выдуманным.
