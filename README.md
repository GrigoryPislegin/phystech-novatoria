# AI-рекрутер МФТИ · Nanimai

Инструмент рекрутера: **одно резюме → набор вакансий → объяснимый рейтинг**. По каждой вакансии — требования, подтверждения из резюме, четыре статуса соответствия и вопросы кандидату. Методологию Nanimai адаптируем под подтверждённый кейс МФТИ.

Наш модуль локальной защиты называется **privacy_core**. Это собственная реализация без `certum_core` и БД, с открытыми локальными Slovnet/Navec. [Запуск и ограничения](docs/24-local-privacy-core.md).

## Подключиться

1. Принять приглашение в приватный репозиторий под своим аккаунтом GitHub.
2. Клонировать проект:

   ```sh
   git clone --branch codex/cli-integration-consultation https://github.com/GrigoryPislegin/hackathon-phystech-nanimai.git
   cd hackathon-phystech-nanimai
   ```

3. Убедиться, что `git branch --show-current` показывает `codex/cli-integration-consultation` и в папке есть prototype/. Команда выше уже выбирает нужную базу.
4. Прочитать [план команды](docs/14-team-kickoff.md) и свою персональную инструкцию выше.

Владелец выдаёт доступ через **Settings → Collaborators → Add people**. Ссылка сама по себе не предоставляет доступ.

## Рабочий процесс

- `main` — общая рабочая версия.
- Для каждой задачи создать отдельную ветку: `git switch -c feature/short-task-name` (для Codex — `codex/short-task-name`).
- Делать небольшие коммиты. В текущем спринте база PR — `codex/cli-recruiter-prototype`; итоговую передачу в `main` выполняет тимлид после интеграции.
- В Pull Request указать результат, выполненные проверки и ограничения; перед слиянием договориться о проверяющем.
- Не загружать ключи, `.env`, личные архивы и данные кейса, пока не подтверждено разрешение на их размещение.

## Запуск и проверки

Из корня проекта:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r prototype/requirements.lock.txt
python -m unittest discover -s prototype/tests -v
python -m prototype demo
```

Текущий runtime — Python 3.13. Certum, PostgreSQL и закрытые артефакты для него не нужны. На Windows без WSL активация: `.venv\Scripts\Activate.ps1`. Путь к отчёту выводится после запуска. Результаты по умолчанию в data/private/prototype-runs/, исключены из Git. Ключ для replay не нужен. [Подробные команды и ограничения](prototype/README.md).

Для необязательной локальной диагностики нужен Python 3.11+:

```sh
python3 scripts/doctor.py
```

Диагностика показывает доступность инструментов на текущем компьютере. Отсутствие инструмента не является ошибкой проекта, пока стек не выбран. [READY.md](READY.md) — исторический отчёт с компьютера владельца, а не требования к окружению команды.
