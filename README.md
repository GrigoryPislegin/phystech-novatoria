# Хакатон · 6 ноября 2026

Общий репозиторий подготовки и работы команды. Пока ожидаем условие: продукт, стек и дедлайн не определены. Код приложения появится после разбора кейса и регламента.

## Подключиться

1. Принять приглашение в приватный репозиторий под своим аккаунтом GitHub.
2. Клонировать проект:

   ```sh
   git clone https://github.com/GrigoryPislegin/hackathon-2026-11-06.git
   cd hackathon-2026-11-06
   ```

3. Прочитать [START_HERE.md](START_HERE.md) и [бриф](docs/01-brief.md).
4. Заполнить свою строку в [таблице команды](templates/team.csv) и согласовать задачу из [бэклога](templates/backlog.csv).

Владелец выдаёт доступ через **Settings → Collaborators → Add people**. Ссылка сама по себе не предоставляет доступ.

## Рабочий процесс

- `main` — общая рабочая версия.
- Для каждой задачи создать отдельную ветку: `git switch -c feature/short-task-name` (для Codex — `codex/short-task-name`).
- Делать небольшие коммиты и отправлять изменения через Pull Request в `main`.
- В Pull Request указать результат, выполненные проверки и ограничения; перед слиянием договориться о проверяющем.
- Не загружать ключи, `.env`, личные архивы и данные кейса, пока не подтверждено разрешение на их размещение.

## Запуск и проверки

Приложения и зависимостей пока нет. После выбора стека здесь появятся точные команды установки, запуска и тестов.

Для необязательной локальной диагностики нужен Python 3.11+:

```sh
python3 scripts/doctor.py
```

Диагностика показывает доступность инструментов на текущем компьютере. Отсутствие инструмента не является ошибкой проекта, пока стек не выбран. [READY.md](READY.md) — исторический отчёт с компьютера владельца, а не требования к окружению команды.
