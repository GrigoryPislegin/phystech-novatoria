# AI-рекрутер МФТИ · Nanimai

Инструмент рекрутера: **одно резюме → набор вакансий → объяснимый рейтинг**. По каждой вакансии — требования, подтверждения из резюме, четыре статуса соответствия и вопросы кандидату. Методологию Nanimai адаптируем под подтверждённый кейс МФТИ.

## Текущее состояние

Подготовлен первый CLI без UI и Docker: локальное чтение документов, схемы оценки, проверка цитат, скоринг, JSON/CSV/Markdown отчёты. Встроенный пример работает без сети и явно помечен **synthetic replay — не ответ модели**.

Код обращения к OpenAI и адаптер настоящего Certum подготовлены, но полный реальный путь ещё не проверен: ключ владелец добавит позже, Certum требует настроенного core, PostgreSQL/tenant/vault и локальных моделей. Нельзя называть защиту подключённой только по наличию адаптера. Реальные документы без неё не отправляются. Luna — модель по умолчанию, Sol выбирается явно.

Консультация по последнему сообщению владельца: 13 ноября 2026, 14:00 МСК. Финальная сдача: 14 ноября, 23:59 МСК. К финалу остаются требования упаковки Docker и воспроизводимого запуска. Командный пакет и прототип находятся в ветке [`codex/cli-recruiter-prototype`](https://github.com/GrigoryPislegin/hackathon-phystech-nanimai/tree/codex/cli-recruiter-prototype). Начинать работу от неё; в main изменения отдельно принимает тимлид.

## Подключиться

1. Принять приглашение в приватный репозиторий под своим аккаунтом GitHub.
2. Клонировать проект:

   ```sh
   git clone --branch codex/cli-recruiter-prototype https://github.com/GrigoryPislegin/hackathon-phystech-nanimai.git
   cd hackathon-phystech-nanimai
   ```

3. Убедиться, что `git branch --show-current` показывает `codex/cli-recruiter-prototype` и в папке есть prototype/. Команда выше уже выбирает нужную базу.
4. Прочитать [план команды](docs/14-team-kickoff.md) и свою персональную инструкцию выше.

Владелец выдаёт доступ через **Settings → Collaborators → Add people**. Ссылка сама по себе не предоставляет доступ.

## Рабочий процесс

- `main` — общая рабочая версия.
- Для каждой задачи создать отдельную ветку: `git switch -c feature/short-task-name` (для Codex — `codex/short-task-name`).
- Делать небольшие коммиты и отправлять изменения через Pull Request в `main`.
- В Pull Request указать результат, выполненные проверки и ограничения; перед слиянием договориться о проверяющем.
- Не загружать ключи, `.env`, личные архивы и данные кейса, пока не подтверждено разрешение на их размещение.

## Команда и агенты

- **Григорий:** продукт, интеграция, контракты, защита и скоринг.
- **Егор:** продуктовые вопросы и независимая проверка через Claude, включая **Opus**. Ручная разметка всего набора не требуется.
- **Ваня:** документы, запуск на другом компьютере и выделенные части кода через Codex.

Общая библиотека навыков — закреплённые Superpowers. Для Codex: `python3 scripts/setup_agents.py`; для Claude: `python3 scripts/setup_claude.py`. Сначала загрузить указанную в персональных инструкциях версию в vendor/superpowers. Один основной агент и максимум один помощник одновременно; без отдельной оркестрационной платформы и платного API для разработки. OpenAI API продукта — отдельный бюджет $74.

Ключи, реальные CV, личные архивы и приватные отчёты не помещать в Git, PR, промпты агентов или логи. Использовать вымышленные данные для разработки. Детекторы не гарантируют полной анонимности; ограничения подробно описаны в архитектуре.

## Запуск и проверки

Из корня проекта:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r prototype/requirements.lock.txt
python -m unittest discover -s prototype/tests -v
python -m prototype demo
```

Предпочтителен Python 3.12 для совместимости с Certum; автономный CLI также проверяется на 3.13. На Windows без WSL активация: `.venv\Scripts\Activate.ps1`. Путь к отчёту выводится после запуска. Результаты по умолчанию в data/private/prototype-runs/, исключены из Git. Ключ для replay не нужен. [Подробные команды и ограничения](prototype/README.md).

Для необязательной локальной диагностики нужен Python 3.11+:

```sh
python3 scripts/doctor.py
```

Диагностика показывает доступность инструментов на текущем компьютере. Отсутствие инструмента не является ошибкой проекта, пока стек не выбран. [READY.md](READY.md) — исторический отчёт с компьютера владельца, а не требования к окружению команды.
